## 用户场景与测试

### US1 已登录用户安全修改密码（P1）

用户从设置中修改密码，输入原密码、新密码和确认密码，不通过邮件链接完成操作。

优先原因：当前已有密码账号没有改密入口；旧设密入口只依赖登录会话，不能以可编辑的“已设密”标志作为安全边界。

独立验收：在隔离测试账号验证正确原密码成功、错误原密码拒绝，修改不影响账号编号和衣橱。

1. 已登录正式账号输入正确原密码和一致新密码，仅同一账号密码可被修改。
2. 未登录、体验身份、错误原密码、缺少字段、身份不一致时，不执行密码修改。
3. 直接调用旧设密入口，也必须验证原密码，不能靠隐藏界面代替检查。
4. 新用户注册保持邮箱与密码直接提交；体验身份注册同时设置邮箱和密码，不在应用层分成两个认证写入步骤。
5. 历史已绑定无密码账号不会被自动改密、清空或迁移；提示保留当前登录并等待安全恢复方案。

### US2 项目负责人掌握真实上架进度（P1）

以 progress.md 为唯一进度入口；本阶段产出数据流清单、注销设计边界和发布证据门禁，不能将本地通过写成已经上架。

独立验收：每个未完成的上架门禁都有责任方、缺少的证据和下一步；未确认的运营主体、联络方式、保留期和备案信息不发布为正式协议。

### 边界情况

- 两次密码不同、全空字段、异常表单类型、多字节密码超长、新旧相同。
- 认证服务限流、要求额外验证、网络中断、改密已成功但临时验证会话退出失败。
- 临时验证身份与当前账号不同；用户可编辑资料标志与真实密码状态不一致。
- 当前账号已有多设备会话；不承诺旧访问令牌即时失效。

## 功能要求

- FR-001：设置中提供明确的改密入口，沿用品牌与日夜皮肤，字段可粘贴并支持密码管理器。
- FR-002：所有改密必须以服务端确认的当前账号与正确原密码为前提；用户提交的邮箱、账号编号、资料标志不决定授权。
- FR-003：不记录、回显或持久保存密码；结果仅返回安全的状态与字段提示。
- FR-004：旧设密入口与新界面执行同一规则。历史无密码账号不得成为绕过原密码验证的例外。
- FR-005：常规注册仍不发送注册确认或密码设置邮件；体验注册避免应用层先绑定邮箱后单独设密的中间状态。
- FR-006：等待时防止重复提交；错误可定位到字段；成功清空输入；不向用户保证未经验证的全设备退出。
- FR-007：认证状态、原图、贴纸、日记、资讯、天气的数据流分别有核实记录；地域与合同保留期限未知时明确标为待确认。
- FR-008：必须列出账号注销、找回密码、隐私授权、国内备案、AI登记/标识、iOS客户端、真机验收、商店素材等后续门禁。
- FR-009：本阶段只本地实现与离线验证，不修改生产认证开关、不建立管理员远程改密接口、不删除真实数据、不部署。

## 关键实体

- 改密申请：当前密码、新密码、确认密码；仅处理期间存在。
- 当前身份：由认证服务确认的账号编号、邮箱、匿名状态。
- 发布证据：门禁、状态、责任方、验收方式；不包含凭据或真实个人资料。
