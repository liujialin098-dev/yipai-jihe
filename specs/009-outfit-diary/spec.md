# Feature Specification: 穿搭日记与基础衣物利用率报告

**Feature Branch**: `009-outfit-diary`

**Created**: 2026-08-28

**Status**: Complete

**Input**: User description: "添加穿搭日记和衣物利用率报告。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 记录当天实际穿搭 (Priority: P1)

用户穿好一套衣服后，希望把当天实际穿着的单品记录下来。用户既可以从今日推荐中一键记入，也可以从当前衣橱手工选择 1～8 件衣物组成记录。

**Why this priority**: 日记记录是利用率报告的唯一可信数据来源，必须先保证写入简单、可修改且不会重复计数。

**Independent Test**: 在今日推荐中选择一套保存，再进入日记查看当天记录；随后编辑为手工组合并再次保存，确认当天仍只有一条记录且穿着单品已更新。

**Acceptance Scenarios**:

1. **Given** 用户已有今日推荐，**When** 点击某套搭配的“记为今日穿搭”，**Then** 系统从服务端重新读取该推荐，只保存当前用户真实拥有的单品。
2. **Given** 用户进入手工记录页，**When** 选择日期、场合和 1～8 件当前衣物并保存，**Then** 日记显示该日期、衣物和可选短记。
3. **Given** 同一天已有记录，**When** 用户再次保存推荐或手工组合，**Then** 系统更新当天记录而不是新增第二条。
4. **Given** 用户查看已有日记，**When** 点击编辑或删除，**Then** 可以修改当天组合或确认删除整条记录。

---

### User Story 2 - 回顾穿搭历史 (Priority: P1)

用户希望按月份回看哪些天记录过穿搭，并快速看到最近记录中的衣物、场合和短记。

**Why this priority**: 历史回顾让日记具备持续使用价值，也为用户检查利用率统计是否可信提供直接证据。

**Independent Test**: 创建本月两个不同日期的记录，切换月份并返回，确认月份摘要、日期顺序和记录详情正确。

**Acceptance Scenarios**:

1. **Given** 本月存在多条日记，**When** 打开日记页，**Then** 页面按日期倒序显示记录并标出本月已记录天数。
2. **Given** 用户选择上月或下月，**When** 月份变化，**Then** 页面只显示目标月份的记录，且不能导航到未来月份。
3. **Given** 某条记录中的衣物后来被归档或删除，**When** 用户回看历史，**Then** 已保存的衣物名称快照仍可读，不把记录静默删除。

---

### User Story 3 - 查看基础衣物利用率 (Priority: P2)

用户希望查看近 30 天、近 90 天或全部记录中的衣橱利用情况，知道哪些衣物常穿、哪些穿得少、哪些还没有记录过。

**Why this priority**: 统计建立在前两个故事的真实记录上，能够帮助用户优先复穿或整理闲置衣物，但不阻塞日记核心路径。

**Independent Test**: 为固定测试衣物创建多天记录，分别切换 30 天、90 天和全部范围，确认总利用率、穿着次数、最后穿着日期和未穿单品一致。

**Acceptance Scenarios**:

1. **Given** 当前日常衣橱有 20 件、范围内 8 件至少穿过一次，**When** 查看报告，**Then** 总利用率显示为 40%。
2. **Given** 同一件衣物出现在 3 天记录中，**When** 查看单品排行，**Then** 其穿着次数为 3，并显示最近一次穿着日期。
3. **Given** 某件当前日常衣物在范围内没有日记记录，**When** 查看未穿列表，**Then** 该单品显示为“未记录穿着”。
4. **Given** 范围内没有任何日记，**When** 查看报告，**Then** 页面显示 0 次和清晰的开始记录入口，不生成虚假趋势或 AI 结论。

### Edge Cases

- 推荐内容已经刷新、删除或不再属于当前用户时，一键记录必须失败并提示刷新，不接受客户端提交的整套内容。
- 手工提交包含重复、无效、已删除、他人或超过 8 件的衣物 ID 时，必须拒绝整次保存。
- 日记日期不得晚于账号城市时区下的今天；明日推荐不能提前计入已穿次数。
- 同一天并发保存时，数据库唯一约束必须保证最终最多一条记录。
- 修改当前衣着偏好后，报告分母和手工候选只使用当前偏好允许的日常衣物；历史快照继续可读。
- 删除日记必须同时移除该日对利用率的贡献，且不能删除任何衣物或推荐。
- 私有衣物图片签名地址过期或原衣物已删除时，页面仍显示文字快照，不出现破损图片占位。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 为每名用户每天最多保存一条穿搭日记，并以账号城市时区解释“今天”。
- **FR-002**: 日记 MUST 保存日期、标题、场合、来源、1～8 个去重衣物 ID、衣物文字快照、可选短记及创建/更新时间。
- **FR-003**: 推荐一键记录 MUST 只接收推荐 ID 和套装位置，服务端重新读取当前用户推荐并验证其中衣物归属。
- **FR-004**: 明日或更晚的推荐 MUST NOT 计入穿搭日记和利用率。
- **FR-005**: 手工记录 MUST 只允许选择当前用户当前偏好可见的日常衣物，并在服务端重新验证 1～8 件、无重复和所有权。
- **FR-006**: 同一天再次保存 MUST 更新当天记录；更新结果立即反映在日记和报告中。
- **FR-007**: 用户 MUST 能查看目标月份的历史记录、编辑记录并确认删除记录。
- **FR-008**: 历史记录 MUST 通过不可变文字快照保留保存时的衣物名称、类别、颜色和风格，即使原衣物后来归档或删除。
- **FR-009**: 利用率报告 MUST 支持近 30 天、近 90 天和全部三个范围。
- **FR-010**: 总利用率 MUST 按“范围内至少记录一次的当前日常可见衣物数 ÷ 当前日常可见衣物总数”计算。
- **FR-011**: 报告 MUST 展示记录天数、穿着单品次数、最常穿单品、单品最近穿着日期和未记录穿着单品。
- **FR-012**: 所有日记读取和写入 MUST 由当前 Supabase Auth 用户确定身份，并由 RLS 阻止跨用户访问。
- **FR-013**: 数据库 MUST 验证日期唯一、字段范围、衣物数量和衣物所有权，客户端校验不得作为唯一安全边界。
- **FR-014**: 日记和报告入口 MUST 在现有移动端主导航或首页中清晰可见；现有收藏能力仍保留可达。
- **FR-015**: 页面 MUST 延续现有冷白银灰、软圆角、系统蓝焦点、分层显现和减少动态/透明度降级，不恢复黑色按钮白色扫光。
- **FR-016**: 本阶段 MUST NOT 增加穿搭照片上传、提醒、分享、购买价格、单次穿着成本、AI 长报告或日记偏好加权。
- **FR-017**: 本阶段 MUST NOT 新增第三方依赖、客户端服务密钥或跨用户聚合。

### Key Entities

- **穿搭日记记录**: 当前用户某一自然日的唯一记录，包含来源、场合、短记、衣物 ID 和保存时文字快照。
- **衣物快照**: 保存时每件衣物的 ID、名称、类别、主色和风格；用于原衣物变化后的历史回顾，不作为当前衣橱权限替代。
- **利用率报告**: 从当前用户日记与当前日常可见衣橱即时计算的范围统计，不单独持久化。
- **推荐来源引用**: 可选关联到当日推荐及套装位置；推荐变化后日记仍以自身快照为准。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可在今日推荐卡中 1 次点击完成当天记录，或在手工页 60 秒内完成一次记录。
- **SC-002**: 同一用户同一天连续保存 3 次后，数据库记录数始终为 1，最后一次组合正确生效。
- **SC-003**: 两个隔离账号互相读取、修改或删除对方日记的成功率为 0%。
- **SC-004**: 固定样本中 30 天、90 天和全部范围的记录天数、总利用率、单品次数与最后穿着日期计算准确率为 100%。
- **SC-005**: 删除一条日记后，相关单品穿着次数和总利用率在下一次页面读取时正确减少。
- **SC-006**: 390px 宽度下，日记列表、手工选衣和报告无水平溢出，主操作无需缩放即可完成。
- **SC-007**: 页面不调用 AI 生成统计文案；无记录时虚构穿着次数、趋势或天气的数量为 0。

## Assumptions

- 日记代表“实际穿过”，不是未来计划，因此只允许记录账号城市时区下的今天或过去日期。
- 当前 `wardrobe_items` 没有可靠购买价格，基础报告不展示单次穿着成本。
- MVP 数据量按每名用户每天一条设计；报告在服务端读取目标范围后即时聚合，无需物化视图或定时任务。
- 日记中的短记是可选的简短文本，不支持富文本、照片或位置。
- 当前收藏入口可以从日记页继续访问，底部主导航优先让位给更高频的“记录”。
