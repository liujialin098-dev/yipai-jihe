# Feature Specification: IP 天气城市建议

**Feature Branch**: `019-ip-weather-suggestion`

**Created**: 2026-08-27

**Status**: Complete

**Input**: User description: "可以按照 IP 更换所在城市的天气吗？按推荐方案实现：IP 只负责发现可能所在城市，不静默覆盖；用户可选择本次使用或设为常用城市。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 发现可能所在城市 (Priority: P1)

用户出差或旅行后打开推荐页，希望系统发现自己可能已经离开常用城市，但必须先由本人确认，不能在后台悄悄更换天气。

**Why this priority**: 错误城市会直接破坏天气和穿搭可信度，而 IP 定位本身可能受运营商、代理或 VPN 影响，因此“发现但不擅自修改”是核心安全边界。

**Independent Test**: 账号常用城市为武汉，请求位置显示杭州时，推荐页出现杭州建议；用户不点击任何操作时，当前天气城市和已保存城市仍保持武汉。

**Acceptance Scenarios**:

1. **Given** 请求位置与当前天气城市明显不同，**When** 用户打开推荐页，**Then** 页面提示“可能在新城市”，并说明 IP 结果可能不准确。
2. **Given** 页面显示新城市建议，**When** 用户不确认或关闭页面，**Then** 系统不得修改本次天气城市、账号常用城市或现有推荐。
3. **Given** 请求缺少可用位置、位置仍在当前城市附近或不在当前支持范围，**When** 用户打开推荐页，**Then** 页面不展示误导性的切换提示，继续使用当前选择城市。

---

### User Story 2 - 选择本次使用或设为常用城市 (Priority: P1)

用户确认 IP 建议城市后，可以只在当前浏览器会话使用，也可以把它保存为账号常用城市；临时切换后还可以一键恢复。

**Why this priority**: 出差和搬家是不同需求。把临时选择与永久保存分开，既减少反复修改，也避免一次旅行覆盖跨设备偏好。

**Independent Test**: 武汉账号检测到杭州后，先选择“本次使用”，确认当前天气变为杭州但账号常用城市仍为武汉；恢复后回到武汉。再次选择“设为常用城市”，确认刷新和重新登录后仍为杭州。

**Acceptance Scenarios**:

1. **Given** 页面显示杭州建议，**When** 用户选择“本次使用”，**Then** 当前浏览器会话使用杭州真实天气，账号常用城市仍保持原值。
2. **Given** 当前使用临时城市杭州，**When** 用户点击“恢复武汉”，**Then** 临时选择被清除，天气城市恢复为账号常用城市武汉。
3. **Given** 页面显示杭州建议，**When** 用户选择“设为常用城市”，**Then** 杭州写入当前账号并跨刷新、重新登录和设备恢复。
4. **Given** 城市确认、保存或真实天气获取失败，**When** 操作结束，**Then** 页面显示通俗错误，不使用虚构天气，也不错误覆盖原城市。

### Edge Cases

- IP 城市名经过编码、为空、过长、经纬度无效或国家不在当前支持范围时，不展示建议。
- VPN、公司网络、移动运营商出口或 CDN 识别可能造成偏差，页面必须明确结果仅供确认。
- IP 城市与当前城市名称写法不同但地理位置接近时，不重复提示。
- 临时城市只对创建它的当前账号和当前浏览器会话生效；退出后登录另一账号不得继承。
- 临时或永久切换城市后，今天与明天的旧城市推荐都必须失效，避免继续展示旧天气。
- 手动“选择城市”入口继续可用，且手动保存常用城市时应清除旧的临时选择。
- 本地开发、预览环境或隐私网络没有 IP 位置时，系统继续使用手动城市，不回退到武汉、北京或任何模拟位置。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 只把请求位置用于生成待确认建议，不得静默修改当前天气城市或账号常用城市。
- **FR-002**: 系统 MUST 只在位置字段完整、位于当前支持国家且与当前天气城市明显不同时显示建议。
- **FR-003**: 页面 MUST 告知用户 IP 位置可能受 VPN、运营商或网络出口影响。
- **FR-004**: 用户 MUST 能选择“本次使用”，让建议城市仅在当前浏览器会话中生效。
- **FR-005**: 用户 MUST 能选择“设为常用城市”，让建议城市保存到当前账号并跨会话恢复。
- **FR-006**: 临时选择 MUST 与创建它的账号绑定，另一账号不得读取或继承该临时城市。
- **FR-007**: 临时选择 MUST 提供恢复账号常用城市的明确操作。
- **FR-008**: 临时和永久切换 MUST 先把城市解析为受支持的规范城市，失败时保持原状态。
- **FR-009**: 任何有效城市切换或恢复 MUST 使当前账号今天与明天的旧推荐失效。
- **FR-010**: 推荐生成和读取 MUST 使用当前有效城市：临时城市优先，否则使用账号常用城市。
- **FR-011**: 新生成推荐 MUST 只使用当前有效城市的真实天气；天气失败不得使用模拟天气、默认城市或旧城市结果。
- **FR-012**: 手动城市选择 MUST 继续可用；保存手动城市后 MUST 取消旧的临时城市。
- **FR-013**: IP 位置不可用、不完整或不可靠时 MUST 保持安静，并继续使用用户已选择的城市。
- **FR-014**: 页面 MUST 清楚区分“本次使用”和“常用城市”，避免用户误以为临时选择已跨设备保存。
- **FR-015**: 本阶段 MUST NOT 新增持续设备定位、浏览器定位权限、默认武汉/北京、海外城市支持、模拟天气或新的个人位置历史。
- **FR-016**: 本阶段 MUST NOT 新增数据库迁移、第三方依赖、公开定位接口或浏览器可读的服务端位置状态。

### Key Entities

- **IP 城市建议**: 当前请求携带的近似城市、国家、区域和经纬度，只用于判断是否向用户展示待确认建议，不直接成为天气来源。
- **本次天气城市**: 当前账号在当前浏览器会话内确认的临时规范城市，优先于账号常用城市，可恢复且不跨账号继承。
- **账号常用城市**: 已有的账号级规范城市、行政区、坐标和时区，跨会话与设备恢复。
- **当前有效城市**: 推荐读取和生成实际采用的城市；本次天气城市存在时优先，否则为账号常用城市。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 请求位置与当前城市相距至少 50 公里时，符合支持范围的测试请求 100% 展示待确认建议，未确认前城市修改数为 0。
- **SC-002**: 用户可在 2 次点击内完成“本次使用”，并在 1 次点击内恢复常用城市。
- **SC-003**: 临时切换后，新推荐使用建议城市真实天气的比例为 100%，账号常用城市变更数为 0。
- **SC-004**: 永久保存后，刷新、退出重新登录和另一设备会话读取到新常用城市的成功率为 100%。
- **SC-005**: 两个隔离账号互相继承临时城市或修改对方常用城市的成功率为 0%。
- **SC-006**: IP 位置缺失、无效、同城或不受支持时，错误城市提示和默认城市回退发生率均为 0%。
- **SC-007**: 390px 宽度下，建议卡、双操作按钮、恢复入口和手动城市选择无水平溢出。

## Assumptions

- 用户已认可“IP 仅作建议、由本人确认”的推荐方案，不需要再次确认产品边界。
- “明显不同”采用约 50 公里距离门槛，减少同城不同出口或邻近机房造成的重复提示。
- 当前自动建议只支持中国大陆城市，与既有手动城市解析范围保持一致；其他国家和地区继续使用手动入口。
- 本次使用通过浏览器会话状态保存，浏览器会话结束后自然失效；账号常用城市继续使用现有账号字段。
- IP 定位为城市级近似结果，不保存 IP 地址，不建立位置轨迹，也不用于授权判断。
