# SDD-030：国内搭配 AI 与轻量紫色界面

**阶段**：030-domestic-ai-simplify ｜ **创建**：2026-09-06 ｜ **状态**：规格确认

用户输入：换国内 AI，取消穿搭卡片与抠图，参考 Whering 但保持自己的品牌。添加衣物必须位于底部正中且最突出。最新视觉反馈覆盖首版深紫方案：背景改为浅、灰调且高级的雾丁香渐变；按钮按自身语义色反馈，底部导航不得整块变色。英文品牌名采用 Ensemble，并使用好看且克制的时尚字体。后续补充：每套搭配名称应随场景与风格变化，大模型应利用用户长期喜好和每日更新的可信时尚动态；顶部改为悬浮式青柠色。最新导航决策覆盖上一版：顶部左侧增加圆形穿搭日记入口，品牌保持居中，右侧圆形头像仍进入个人主页；底部固定为首页、衣橱、中央添加衣物、推荐穿搭、时尚资讯五项，收藏与利用率继续保留在日记页内。中央添加按钮由圆形改为四角切面的倒角矩形，底部继续使用浅紫材质并与顶部厚度接近。

## 用户场景与验收

### US1 清楚找到主要功能（P1）

用户进入已登录 App，可通过五个底部入口直达首页、衣橱、添加衣物、推荐穿搭和时尚资讯；穿搭日记通过顶部左侧圆形入口进入，个人主页通过顶部右侧圆形头像进入。日记内直接切换收藏与利用率。

独立验收：390px 与桌面宽度检查导航顺序、选中状态、中心添加按钮大小和目标路径；未登录仍只出现身份入口。

1. 已登录时点击中间加号，进入添加衣物，不进入卡片或收藏。
2. 用户悬停、触按或键盘聚焦按钮时，黑白紧凑控件可得到克制紫色反馈，其他彩色控件基于原色变化，危险操作保持红色；底部普通导航只显示浅紫气泡与轻微位移，中央添加按钮单独变色，导航项本体不铺满深紫；禁用按钮不可操作。
3. 首页与推荐标题更小、圆润、居中，正文保持易读；减少动态偏好仍生效。
4. 顶部青柠栏只保留品牌和圆形头像，与页面四周留有呼吸空间；底部为浅紫栏，两者视觉厚度接近，滚动和小屏下不遮挡标题、头像或主要操作。
5. 旧 `/favorites` 地址自动进入日记中的收藏分页，不丢失现有收藏内容或收藏按钮能力。

### US2 精简搭配流程（P1）

用户查看衣物原图组成的搭配，继续换件、收藏及记日记，不再需要画布编辑、分享卡片和抠图。

独立验收：推荐页和个人页不存在旧入口；旧链接不再打开编辑器；旧处理接口不执行抠图；确认衣物不会触发自动去背。

1. 旧画布链接跳转至推荐，历史衣物、照片、画布记录不被删除。
2. 个人主页保留昵称头像编辑、衣物数、日记数及利用率，不再展示卡片作品区。

### US3 使用国内搭配模型（P1）

每日搭配由国内模型生成；失败原因能够区分配置缺失、鉴权、限流、超时及不合格结果。只有真实天气成功时才允许规则后备。

独立验收：固定模拟响应覆盖成功及各类失败；配置真实凭据后再验证三个完整合法方案与模型来源。

1. 国内模型成功后仅保存当前账号的合法衣物组合及实际请求模型名。
2. 服务失败或输出不合法只降级一次，不调用旧国外推荐模型，不伪造 AI 成功。
3. 失败日志不包含密钥、图片、昵称、邮箱、衣物内容或模型原文。

### US4 获得贴合本人且跟得上趋势的搭配（P1）

用户每天生成搭配时，结果同时考虑自己明确选择、收藏/换件等历史反馈，以及当天仍有效且有来源的时尚动态；每套名称与实际风格、场景和天气一致，而不是反复出现固定模板。

独立验收：使用固定用户偏好、固定趋势信号和同一衣橱生成三套方案，检查名称差异、偏好命中、趋势来源与过期降级；无历史偏好或无有效趋势时仍能稳定生成，不冒充“最新”。

1. 三套名称在同一批次内不得重复，应能从名称看出主要风格或穿着情境，且不得写入与单品冲突的风格。
2. 用户明确选择与长期反馈优先于流行趋势；趋势只能在天气、性别/衣着归属、场景、库存和完整性都合法时影响排序与表达。
3. 只有带来源、发布时间且仍在有效期内的内容才能作为当天趋势信号；来源不可用或内容过期时，推荐继续使用个人偏好与衣橱，但不声称来自最新动态。
4. 用户关闭个性化时，不读取其衣橱反馈或穿着历史来调整风格；用户之后重新开启时可继续使用已有合法偏好。

## 边界

- 空衣橱、长标题、名称重复、无头像、旧链接、旧客户端、键盘导航、小屏、滚动状态及减少动态。
- 缺凭据、错误地域、权限不足、429、网络中断、截断响应、非法 JSON 与场景冲突。
- 用户无偏好历史、偏好与趋势冲突、趋势源为空、日期缺失、来源过期或资讯拉取失败。
- 取消卡片不等于取消普通内容卡片，也不删除历史资产。

## 功能要求

- FR-001：底部严格五项：首页、衣橱、居中突出的添加衣物、推荐穿搭、时尚资讯；中央添加控件必须为倒角矩形而非圆形。顶部青柠栏不得显示文字导航，左侧圆形按钮进入穿搭日记，右侧圆形头像进入个人主页。日记页必须提供日记、收藏、利用率三栏，旧收藏路由安全重定向到收藏栏。
- FR-002：使用自己的 `Ensemble / 衣拍即合` 双语品牌及圆润标题；英文字标使用自托管 OFL 展示字体，中文与正文不使用该字体。背景使用浅灰调雾丁香并保持对比度；底部 Dock 不得复用通用按钮的整块紫色填充状态，彩色控件必须保留语义色，大面积 UI 只允许轻量明暗、边框或景深反馈。
- FR-003：停用卡片及所有抠图入口和处理端点，保留历史数据。
- FR-004：个人资料编辑、收藏、日记、天气与衣物识别继续可用。
- FR-005：推荐切换国内服务，保持天气、归属、场景、分层及跨套不重复规则。
- FR-006：模型请求有时间上限且不自动重试；失败可诊断且安全降级。
- FR-007：配置只在服务端读取，未完成真实模型验收不得标记正式接入成功。
- FR-008：每套搭配名称必须由该套实际场景、首要风格、天气或关键单品共同决定；同批三套名称唯一，禁止固定编号和重复套话。
- FR-009：模型输入必须包含当前账号允许使用的长期风格偏好与反馈摘要；不得传递昵称、邮箱、原始反馈记录或其他非必要身份数据。
- FR-010：模型可接收当天有效的趋势主题摘要，但每条摘要必须有可追溯来源和日期；不得传递外站全文或图片，也不得将过期内容描述为当前趋势。
- FR-011：偏好、天气、衣着归属、场景合法性、衣橱库存和搭配完整性优先于趋势；最终结果仍须通过现有安全复验。
- FR-012：趋势或模型不可用时只允许一次稳定规则后备；后备名称也必须随风格与情境变化，并明确不冒充 AI 或最新趋势结果。

## 关键实体

沿用推荐批次、衣物、用户资料、偏好反馈、时尚内容与日记；新增的用户风格画像、每日趋势信号和搭配名称均为从既有合法数据派生的输入或结果，不新增公开社交资料。历史画布与透明图仅保留。

## 可衡量结果

- SC-001：五个底部入口、顶部日记圆形入口及顶部头像均可达，390px 无水平溢出。
- SC-002：旧处理入口全部停止执行，确认新衣物零抠图请求。
- SC-003：固定失败样本均返回对应受控错误，不泄露请求内容。
- SC-004：配置后真实推荐恰好三套，全部通过既有归属和场景校验。
- SC-005：质量检查和生产构建通过，实际线上发布单独记录。
- SC-006：固定样本的三套名称 3/3 不重复，且 3/3 与各自首要风格或场景一致；规则后备同样满足。
- SC-007：偏好库存允许时，三套中至少两套体现用户高权重风格；与硬规则冲突时 0 套为迎合偏好而违规。
- SC-008：只有当天仍有效且有来源的趋势主题进入推荐；过期、无日期或无来源样本进入数量为 0。
- SC-009：320px 与 390px 下顶部青柠栏和底部浅紫栏无水平溢出；顶部与底部视觉高度差不超过 8px，顶部日记、头像、五个底部入口和日记三栏均可键盘与触控访问。

## 假设与决策

- 国内 AI 首先切换每日推荐至百炼千问；图片识别和资讯摘要暂保留现有模型，本阶段不扩大为所有 AI 重写。
- 每日趋势复用现有时尚资讯白名单与缓存，不新增社交平台爬虫、外站图片复制或无来源热点；趋势影响当次推荐，不直接改写用户长期偏好。
- “学习喜好”指使用用户明确偏好及应用内收藏、换件和穿着反馈形成可解释风格权重，不训练专属基础模型，也不跨账号共享个人数据。
- 不新增付费订阅，不替用户生成或填写账户密码；缺百炼凭据时保存并等待配置。
- 本阶段约一段 AI Coding 主对话；真实凭据联调可另开短对话，不代表生产研发工期。
