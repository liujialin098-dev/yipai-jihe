# Feature Specification: 换一件、收藏与偏好反馈

**Feature Branch**: `006-outfit-feedback`

**Created**: 2026-08-24

**Status**: Draft

**Input**: SDD-006 在现有每日三套推荐上增加单品替换、单品与整套收藏、可跳过的冷启动偏好问卷，以及可解释的行为偏好加权。

## Clarifications

### Session 2026-08-24

- Q: 整套收藏是否随今日推荐后续刷新而改变？ → A: 不改变，保存收藏时快照。
- Q: 换掉旧单品是否视为“不喜欢”？ → A: 不视为负向，只给换入单品较小正向权重。
- Q: 冷启动问卷如何控制复杂度？ → A: 单页 3 题，可跳过并写入稳定默认值。
- Q: 没有合法同类候选时是否允许推荐衣橱外商品？ → A: 不允许，保留原方案并说明无候选。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 换掉不合适的单品 (Priority: P1)

作为已经得到今日三套推荐的用户，我可以点开任意单品，从自己衣橱中选择一件更合适的同类单品替换，并立即看到仍然完整、无重复的更新方案。

**Why this priority**: 推荐不是一次性答案；允许局部调整才能让用户真正把方案穿出门。

**Independent Test**: 加载演示衣橱并生成推荐，替换其中一件上装；确认新单品来自当前用户、类别相同、未在其他两套出现，刷新后结果保持。

**Acceptance Scenarios**:

1. **Given** 今日推荐包含可替换单品，**When** 用户打开“换一件”，**Then** 系统展示当前用户衣橱中类别相同、状态有效且未被今日三套使用的候选。
2. **Given** 用户选择合法候选，**When** 确认替换，**Then** 当日推荐原位更新并重新通过完整性、天气、场合和跨套去重校验。
3. **Given** 没有合法候选或请求失败，**When** 用户尝试换件，**Then** 原方案保持不变并显示可理解原因。

---

### User Story 2 - 收藏单品与整套穿搭 (Priority: P2)

作为用户，我可以收藏喜欢的衣物或整套推荐，在独立收藏页再次查看，并随时取消收藏。

**Why this priority**: 收藏把当天灵感变成可回看的长期资产，也是最明确的正向偏好信号。

**Independent Test**: 收藏一个单品和一套推荐，刷新并进入收藏页；确认两类内容均存在，取消后立即消失且其他用户不可见。

**Acceptance Scenarios**:

1. **Given** 用户查看衣物或推荐卡，**When** 点击收藏，**Then** 收藏状态立即更新且重复点击不会创建重复记录。
2. **Given** 用户刷新了今日推荐，**When** 打开收藏页，**Then** 已收藏整套仍按收藏时快照可见。
3. **Given** 用户取消收藏，**When** 页面重新验证，**Then** 对应收藏消失且原衣物或今日推荐不被删除。

---

### User Story 3 - 建立并理解个人偏好 (Priority: P3)

作为首次使用推荐的用户，我可以通过 3 题问卷快速选择常用风格与场合，也可以跳过；之后收藏和换件会小幅更新偏好，并能说明变化来源。

**Why this priority**: 有初始偏好可减少随机感，可解释反馈又能避免用户觉得系统在暗中改变选择。

**Independent Test**: 完成或跳过问卷，执行一次换件和一次收藏；确认推荐输入中的偏好顺序更新，设置页能列出问卷、收藏和换件带来的分数来源。

**Acceptance Scenarios**:

1. **Given** 偏好尚未初始化，**When** 用户进入偏好设置，**Then** 可以回答 3 题或跳过并保存默认值。
2. **Given** 用户收藏单品或整套，**When** 操作成功，**Then** 相关风格获得明确正向权重并记录来源。
3. **Given** 用户换入一件衣物，**When** 替换成功，**Then** 新衣物风格获得较小正向权重；被换出的衣物不自动记为“不喜欢”。
4. **Given** 用户查看偏好说明，**When** 展开来源，**Then** 可以区分问卷、收藏和换件贡献。

### Edge Cases

- 当前单品已归档、候选在提交前被归档或候选已出现在其他套时，服务端拒绝替换并保留旧结果。
- 连衣裙只能替换连衣裙；上装、下装、鞋、外套和配饰也只能同类替换。
- 替换后若不再满足冷天外套、完整基底、鞋、季节或场合要求，必须拒绝。
- 今日推荐被刷新后，旧收藏整套仍显示收藏时快照；快照中的衣物被删除时显示“单品已移除”，不泄露其他用户数据。
- 重复收藏、重复取消、重复提交问卷均需幂等。
- 偏好分数允许负向取消收藏抵消，但不得低于 0；并列时保持稳定顺序。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 为今日推荐中每件衣物提供“换一件”入口，并返回同类合法候选。
- **FR-002**: 候选 MUST 属于当前用户、状态为 active、类别相同、未出现在当前三套其他位置，并符合当前天气季节与场合。
- **FR-003**: 替换 MUST 在服务端重新校验完整基底、鞋、冷天外套、季节、场合和跨套不重复，失败不得修改原批次。
- **FR-004**: 替换成功 MUST 原位更新 `daily_recommendations.outfits` 并记录旧单品、新单品、套装位置和时间。
- **FR-005**: 系统 MUST 支持单品收藏与取消收藏，并保证每名用户每件衣物至多一条收藏。
- **FR-006**: 系统 MUST 支持整套收藏与取消收藏，保存收藏时的标题、理由、标签、天气、场合和衣物 ID 快照。
- **FR-007**: 收藏页 MUST 分区展示单品和整套收藏，并正确处理空状态与已删除单品。
- **FR-008**: 系统 MUST 提供 3 题偏好问卷，覆盖核心风格、常用场合和穿搭侧重点；问卷可跳过。
- **FR-009**: 完成或跳过问卷 MUST 写入明确状态；跳过时采用稳定默认偏好。
- **FR-010**: 问卷、收藏、取消收藏和换入单品 MUST 记录可追溯反馈事件，并按固定权重更新风格分数。
- **FR-011**: 被换出的单品 MUST NOT 自动记录为负向“不喜欢”信号。
- **FR-012**: 推荐生成 MUST 使用当前风格分数排序后的前 3 项作为偏好输入。
- **FR-013**: 偏好设置 MUST 展示当前风格排序、分数和问卷/收藏/换件来源摘要。
- **FR-014**: 所有收藏、反馈和偏好数据 MUST 绑定当前 Auth 用户并通过 RLS 隔离。
- **FR-015**: 所有操作 MUST 有加载、成功、无候选、冲突与失败反馈，并支持 390px 键盘操作。
- **FR-016**: 本阶段 MUST NOT 实现“不喜欢”、穿搭日记、协同过滤、模型训练或跨用户推荐。

### Key Entities

- **Item Favorite**: 当前用户对一件衣物的收藏关系。
- **Outfit Favorite**: 当前用户保存的一套推荐快照，不依赖今日批次后续变化。
- **Preference Feedback Event**: 问卷、收藏、取消收藏或换件产生的可解释信号。
- **Preference Profile**: 现有用户偏好的初始化状态与各风格累计分数。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可在 3 次操作内完成一次候选选择与替换，结果刷新后保持。
- **SC-002**: 自动验证覆盖至少两名用户，交叉读写收藏和反馈均被拒绝。
- **SC-003**: 同一收藏操作连续提交 3 次仍只有一条关系记录。
- **SC-004**: 替换后 3 套仍恰好存在，批次内无重复 ID，且每套满足结构与天气规则。
- **SC-005**: 完成一次问卷、一次收藏和一次换件后，偏好说明能列出 3 类来源并显示稳定分数。
- **SC-006**: `npm run check`、生产构建和 `npm run verify:sdd-006` 全部通过。

## Assumptions

- SDD-005 的当日推荐 JSONB 继续作为可替换快照，不在本阶段拆成子表。
- 候选排序默认使用确定性本地规则；AI 只可重排现有合法候选，失败时不阻塞换件。
- 问卷采用单页 3 题，不增加独立引导流程依赖。
- 密码设置、退出与重登录集中调试继续暂缓，不影响匿名用户完成本阶段。
