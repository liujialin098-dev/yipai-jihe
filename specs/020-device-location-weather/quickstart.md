# Quickstart: 设备定位天气城市验收

## 前置条件

- `.env.local` 已配置当前 Supabase 公开连接变量。
- 使用合成测试账号，不输入真实个人凭据或记录真实精确坐标。
- 本地页面通过 `http://localhost` 访问；Production 必须使用 HTTPS，浏览器才允许定位。

## 自动验收

```powershell
npm run check
npm run build
npm run verify:sdd-020
npm run verify:sdd-018
npm run verify:sdd-019
npm run verify:sdd-013
```

预期：

- 坐标范围、反向响应解析、中国范围、城市字段优先级和异常分支固定样本通过。
- 定位只出现在显式点击处理器中，未使用 Effect、持续定位或高精度模式。
- Server Action 重新鉴权，只接收并再次规范化城市名，不接受客户端用户 ID/设备坐标/行政区/时区。
- 临时/常用城市继续复用现有账号隔离模型，旧推荐在切换后失效。
- 今天/明天真实天气回归通过，无默认武汉/北京或模拟天气。

## 390px 浏览器验收

1. 登录合成账号并打开推荐页，确认页面加载和刷新不弹出定位权限。
2. 展开“选择城市”，确认“使用当前位置”说明、两个按钮和 BigDataCloud 处理说明可见，无横向溢出。
3. 模拟或允许一个受支持中国城市定位，点击“本次使用当前位置”，确认当前城市变化但常用城市不变。
4. 恢复常用城市，再点击“设为常用城市”，确认刷新后仍使用新城市。
5. 分别模拟权限拒绝、超时、不可用和不支持，确认原城市不变且手动输入可用。
6. 定位成功后生成今天/明天推荐，确认城市和真实天气来源一致。
7. 检查 `scrollWidth <= innerWidth`、按钮无重叠、无错误覆盖层和控制台 error。

## 隐私与失败边界

- 不检查或记录测试设备的真实经纬度输出。
- 数据库和 Cookie 只允许出现城市中心五元组，不出现设备原始坐标。
- 客户端城市确认服务不可用时只显示通俗错误，不循环调用或回退默认/IP 城市。
- 未经用户点击不得出现任何定位权限请求。
