# Contract: 设备定位城市动作

## 调用方式

- 仅由已登录推荐页的客户端组件在用户点击定位按钮后调用。
- 输入为 `FormData`，动作返回可序列化的 `WeatherCityActionState`。

## 输入

| 字段 | 必填 | 允许值 |
|---|---|---|
| `city` | 是 | 设备端根据当前坐标确认的 2～80 字符中国城市名 |
| `mode` | 是 | `session` 或 `saved` |

禁止输入或信任：`userId`、纬度、经度、行政区、国家、时区、精度、完整定位对象。城市名仍视为不可信输入，必须再次规范化。

## 服务端处理顺序

1. 读取并校验模式与城市名长度。
2. 通过 Supabase `auth.getUser()` 获取当前用户；无有效用户则失败。
3. 通过既有中国城市解析重新确认城市名并规范化城市中心五元组。
5. 删除当前用户全部旧推荐。
6. `session` 写账号绑定会话 Cookie；`saved` 更新自身偏好并清除临时 Cookie。
7. 刷新推荐与设置页面，返回城市级成功消息。

## 返回

- 成功：`{ status: "success", message, city, admin1 }`
- 失败：`{ status: "error", message }`

错误消息不得包含精确地址、用户 ID、第三方响应正文或内部异常。

## 失败原子性

- 城市规范化失败：不得删除旧推荐，不得修改 Cookie/数据库。
- 删除旧推荐失败：不得切换城市。
- 保存常用城市失败：返回失败，不把定位结果伪装为已持久化。
- 任何失败：原城市继续有效，手动选城继续可用。
