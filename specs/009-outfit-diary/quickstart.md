# Quickstart: SDD-009 独立验收

## 1. 前置条件

1. 当前 Supabase 项目为 `gmjtzmxuveoaqcdmuifr`，状态 `ACTIVE_HEALTHY`。
2. `.env.local` 包含现有 Supabase 公开配置；不新增密钥。
3. 应用日记迁移，并重新生成 `lib/supabase/database.types.ts`。
4. 准备两个隔离测试账号 A/B，各加载至少 8 件演示衣物。

## 2. 自动门禁

```powershell
npm run check
npm run build
npm run verify:sdd-009
```

预期：固定聚合、未来日期、一天唯一、跨用户 RLS、数据库衣物归属、编辑删除和静态页面边界全部通过，测试数据自动清理。

## 3. 推荐一键记录

1. 在今天推荐生成三套搭配。
2. 第一套点击“记为今日穿搭”，前往日记确认日期和全部单品。
3. 返回推荐，第二套再次保存；数据库和页面当天仍只有一条，内容更新为第二套。
4. 切到明天，确认不允许提前记入利用率。

## 4. 手工记录与回顾

1. 打开 `/diary/new`，选择今天以前的日期、场合、1～8 件衣物和短记。
2. 保存后在目标月份看到记录。
3. 编辑该日期，替换一件衣物；确认仍为一条。
4. 删除并确认衣物仍在衣橱、报告次数立即减少。

## 5. 利用率固定样本

- 当前可见日常衣橱 10 件。
- 近 30 天创建 3 条记录：A 出现 3 次，B 出现 2 次，C 出现 1 次，其余 7 件不出现。
- 预期：记录天数 3，穿着单品次数 6，使用单品 3，总利用率 30%；A 最后穿着日期为最新记录日期；未穿列表含其余 7 件。
- 增加一条 31～90 天前记录后，30 天不变，90 天和全部正确增加。

## 6. 隔离与移动端

1. A 尝试读取、更新和删除 B 的日记，全部返回空或拒绝。
2. A 尝试提交 B 的衣物 ID，数据库触发器拒绝整次写入。
3. 390px 浏览器检查 `/diary` 日记/报告和 `/diary/new`：无水平溢出、图片无破损、控制台无 error。
4. 开启减少动态与减少透明度，核心操作仍可完成。

## 7. 已知范围

- 不上传穿搭照片，不提醒，不分享。
- 不统计购买价格和单次穿着成本。
- 不把日记写入偏好分数，不生成 AI 长报告。
- 本阶段完成后先提交代码；只有用户明确要求“更新部署”时才发布 Production。
