# Feature Specification: SDD-028 国内天气与前端直连

**Feature Branch**: `master`（沿用工作区；独立编号 028）  
**Created**: 2026-09-06  
**Status**: Local MVP verified; Production/device-network checks pending
**Input**: 将天气移到前端，接入用户已选择并创建凭据的和风天气；继续今日/明日、手动城市和明确触发的定位，不编造天气。

## User Scenarios & Testing

### US1 看真实天气（P1）

进入推荐页，在生成搭配之前即可看到当前有效城市的天气；切换明日查看该城市下一自然日的最低/最高气温。

独立验收：浏览器网络请求直接到和风天气域名；未登录不签发凭据，私钥不出现在浏览器。

1. Given 已选城市，When 打开今天，Then 显示真实温度、体感、来源和获取时间。
2. Given 同一城市，When 切换明天，Then 精确匹配明日日期，显示最低/最高气温，不伪造最低体感。
3. Given 请求失败/过期/未知天气代码，When 页面加载，Then 明确失败并可重试，不展示默认城市或模拟数据。

### US2 按所在城市查看（P1）

用户保留手动输入、本次城市/常用城市及 IP 建议；设备定位只有本人点击才请求权限，设备坐标只发给和风天气。

独立验收：两个账号城市独立；拒绝定位后手动选城仍可用。

1. Given 城市为空，When 打开页面，Then 提示选城，不默认武汉或北京。
2. Given 用户点击设备定位，When 获得中国城市，Then 应用服务端只接收城市名并重新解析；境外/拒绝/失败不覆盖旧城市。

### US3 搭配依据一致（P1）

生成与灵感排序使用服务端从同一和风天气接口获取并校验的真实天气，不相信浏览器提交的温度；旧结果明确标为生成时快照。

独立验收：篡改天气字段不影响规则依据；城市/日期过期拒绝生成，雨雪映射不混淆。

### Edge Cases

- 跨午夜、错误单位、缺预报日期、NaN、空返回、超时、限流与凭据失效。
- 快速切换城市/日期时取消旧请求，不让迟到响应覆盖新天气。
- 明日昼夜天气不同：显示日间与夜间描述；规则优先雨天防水，雪天不误判为雨。
- 5 分钟后页面天气失效并要求刷新；历史推荐快照不冒充实时数据。

## Requirements

- FR-001 前端直接获取天气；应用仅签发最长 5 分钟的临时访问凭据，服务器保管私钥。
- FR-002 签发接口必须校验当前登录身份、同源请求、有效日期参数，禁止客户端指定用户或服务器请求目标；响应不缓存，限制签发频率。
- FR-003 前后端共用解析规则和日期定义；城市使用当前账号临时城市优先、常用城市兜底，无默认。
- FR-004 明天无真实预报必须停止生成。最低气温作为保守搭配温度时必须明确字段含义，不能称为体感。
- FR-005 保留现有场合/风格/归属/雨天规则；映射天气代码仅作规则分类，同时保留供应商原始代码与描述。
- FR-006 浏览器不持久化访问令牌、设备坐标；同一服务用于城市解析与用户触发的设备城市查询。
- FR-007 旧 Open-Meteo JSON 可读，来源和生成时快照不得误标为和风实时数据。
- FR-008 本阶段不改数据库、衣物、Auth 配置、线上环境或发布；完成后立即更新 progress.md、AGENTS.md 的状态及验收证据。

### Key Entities

WeatherSession（短期 JWT、截止时间、城市中心、目标日期）；WeatherSnapshot（来源、真实温度、温度依据、原始代码、日期、获取时间、归因）；现有账号城市五元组保持不变。

## Success Criteria

- SC-001 check/build、独立天气解析与安全门禁通过；固定雨/雪/未知/跨日样本全部符合预期。
- SC-002 本地浏览器验证真实前端今日/明日请求、未登录拒绝、切换与错误状态、390px 无溢出。
- SC-003 私钥与长期密钥未进入 Git、HTML、客户端构建；天气失败无模拟降级。
- SC-004 未能执行的国内手机无代理、真实定位权限与 Production 验收明确留待用户，不误记完成。

## Assumptions

- 用户已选择和风天气，无需再次确认供应商；已有 JWT 凭据与私钥配对。
- 国内服务降低天气第三方链路的跨境依赖，但应用自身仍在 Vercel/Supabase，不能承诺所有国内网络无障碍。
- API 费用按已有账户配置，不主动开通额外收费产品。
