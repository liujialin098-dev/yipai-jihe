# 功能规格：首次进入引导与自主穿搭

**分支**：沿用当前工作区，不混入未完成注销改动
**创建**：2026-09-16
**状态**：本地实现及隔离验证完成；真实账号/真机验收与发布待执行
**输入**：首次进入有动效的登录注册页，随后选择性别、主题、常用场景及喜爱风格，各步可跳过；首页可自行添加今日穿搭。

## 用户场景与测试

### 场景1：第一次建立衣橱（P1）

用户看到品牌进入页，选择登录或注册。新账号完成身份建立后依次填写四步偏好，再进入空衣橱首页。

**独立验收**：新账号全部选择、全部跳过、混合跳过三条路径均可进入首页；已有账号不反复被要求填写。

1. 给定新注册/新体验身份，完成身份建立后，先出现性别选择而不是首页。
2. 每一步有跳过和下一步，第二步起可返回；已选内容在返回时保留。
3. 全部跳过不改变账号既有默认偏好，不生成演示衣物，完成后重载不再引导。

### 场景2：轻量个性化（P1）

用户可选择男生、女生或不限衣着，六套现有主题、常用场景和喜欢的风格；完成后设置页仍可修改。

**独立验收**：主题有即时预览；场景和风格各1至3项，可增减；跳过不提交该步刚选择的内容；保存失败保留草稿并支持重试。

### 场景3：不用AI也能记录（P1）

用户从首页明显入口记录今日穿搭，从自己的衣橱多选衣物，保存进当日日记。已有当日记录时入口变为编辑。

**独立验收**：未生成任何AI方案也可记录1至8件衣物；无衣物时有添加入口；重复保存更新当天而不重复计数。

### 边界

- 未登录访问引导返回身份入口；已完成/旧账号访问引导返回首页。
- 浏览器存储受限时流程仍可用，只是不保证草稿/设备主题保存；账号完成状态不依赖本地存储。
- 新用户保存断网时不假称成功；部分偏好已保存但完成标记失败时可幂等重试。
- 同一设备换账号不能串用草稿；服务端读取到已完成标记的旧页面请求不再覆盖偏好。不承诺跨标签并发提交的事务互斥。
- 小屏、夜间、长文本、键盘及减少动态模式均有可用入口。

## 功能要求

- FR-001：首次建立账号后展示四步可跳过引导，老用户正常进入。
- FR-002：登录/注册前提供品牌动效和明确操作，不强制等待动画结束。
- FR-003：只保存明确选择的偏好，跳过不推定性别和风格；不将偏好用于权限控制。
- FR-004：主题沿用六套皮肤与现有日夜模式，只影响当前设备；跳过主题撤销本次预览。
- FR-005：保存完成状态随账号保留；身份仍由正常认证决定。
- FR-006：首页新增独立自主记录入口，复用日记并保留AI推荐选项。
- FR-007：加载、失败、重复提交均有反馈，个人数据按当前用户隔离；无演示数据注入。

### 核心对象

- 首次引导状态：仅新账号拥有待完成标记，结束后完成；不代表账号权限。
- 可选偏好：性别对应衣着偏好、设备主题、场景、风格。
- 今日穿搭：当前用户、当地日期、所选衣物、标题、场景、短记。

## 成功标准

- SC-001：用户可在四次跳过后进入首页，不被要求填写任意偏好。
- SC-002：完成后重载或重新登录不再重复展示引导；旧账号行为不变。
- SC-003：首页一次点击即可进入手动今日穿搭编辑页，无需生成AI方案。
- SC-004：320px、375px及横屏无横向溢出；减少动态时步骤不产生位移。

## 假设与范围

- 保留现有明确选择的体验入口，作为次要方式，不自动创建体验身份。
- 性别选择只用于衣着偏好，可不限/跳过，不采集额外法定性别资料。
- 此次不新增AI服务、邮件验证、管理权限、生产迁移、付款或iOS工程；不自动部署。
