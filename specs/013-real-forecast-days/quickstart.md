# Quickstart: SDD-013 独立验收

## 前置条件

- `.env.local` 已配置当前 Supabase 项目。
- 测试账号已保存常用城市并具备可组成三套方案的衣橱。
- 本地运行 `npm run dev`。

## 质量命令

```powershell
npm run check
npm run build
npm run verify:sdd-013
```

## 场景一：今日真实天气

1. 打开 `/recommendations?day=today`。
2. 确认“今天”被选中，点击生成。
3. 对照同一时刻 Open-Meteo 当前天气响应。

预期：页面显示账号城市、今日日期、“Open-Meteo 实时天气”、当前概况和体感温度；没有测试天气下拉框。

## 场景二：明日真实预报

1. 点击“明天”。
2. 确认 URL 为 `?day=tomorrow`，标题和按钮均切换为明日。
3. 点击生成并对照 Open-Meteo 日预报。

预期：页面显示明日日期、“Open-Meteo 明日预报”、明日概况和最低体感温度；生成结果保存到明日日期。

## 场景三：两个日期互不覆盖

1. 今天和明天分别生成一次。
2. 往返切换两个日期并刷新。

预期：两个日期各自读取三套方案；刷新明日不会改变今日方案，数据库最多各一条。

## 场景四：禁止虚构天气

1. 在验证脚本中模拟天气接口失败、字段缺失和目标日期缺失。
2. 尝试生成。

预期：显示真实天气不可用提示；没有 `simulated` 快照，没有新推荐写入，旧模拟批次不展示。

## 场景五：390px UI

检查日期分段控件、场合按钮、生成状态、天气卡和三套推荐。

预期：无水平溢出；日期选中态清晰；今天与明天的所有文案一致；减少动态偏好继续有效。
