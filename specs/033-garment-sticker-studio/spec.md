# Feature Specification: 衣物贴纸册

**Feature Branch**: `master`

**Created**: 2026-09-07

**Status**: Ready

**Input**: User description: "提供一个界面，把每天想穿或喜欢的衣服做成经过抠图、描边与优化的衣物贴纸。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 挑选今天的衣物贴纸 (Priority: P1)

用户进入衣物贴纸册，从全部衣物或收藏单品中选择今天想穿、想搭配的衣物，并立即在一张轻松活泼的贴纸板上看到组合效果。

**Why this priority**: 选择和预览是贴纸册的核心价值，必须先形成独立闭环。

**Independent Test**: 使用已有衣橱选择 1～8 件衣物，刷新页面后确认当天选择仍保留，切换“今日想穿 / 我的喜欢”不会丢失已选状态。

**Acceptance Scenarios**:

1. **Given** 用户有活跃衣物，**When** 进入贴纸册，**Then** 可以从全部衣物中选择 1～8 件并在上方贴纸板同步预览。
2. **Given** 用户收藏过单品，**When** 切换到“我的喜欢”，**Then** 只显示当前账号仍有效的收藏衣物。
3. **Given** 用户刷新同一天的页面，**When** 当前设备仍保留选择，**Then** 有效衣物恢复为已选状态，失效或不再可见的衣物自动剔除。

---

### User Story 2 - 生成白边衣物贴纸 (Priority: P1)

用户选中的衣物如果尚未拥有透明图，可以主动生成贴纸；系统完成专业去背、自动裁边和透明留白后，以白色描边、纸张质感和柔和阴影展示。

**Why this priority**: 真实衣物轮廓和纸贴质感决定该功能是否像“贴纸”而不是普通照片拼图。

**Independent Test**: 混合选择已有透明图与仅有原图的衣物，生成后确认已有贴纸不重复处理、缺少贴纸的衣物逐件完成，并在失败时保留原图和重试入口。

**Acceptance Scenarios**:

1. **Given** 衣物已有透明图，**When** 加入贴纸板，**Then** 立即使用白边贴纸展示且不发起新的去背请求。
2. **Given** 衣物只有原图，**When** 用户点击生成，**Then** 系统只处理当前账号选中的待生成衣物并显示逐件进度。
3. **Given** 第三方去背暂时不可用，**When** 处理失败，**Then** 原图和已成功贴纸保持不变，用户可以稍后重试，不显示内部错误或密钥信息。

### Edge Cases

- 未选择衣物时，生成按钮不可用并提示先选择。
- 选择超过 8 件时不继续增加，并给出简短说明。
- 收藏为空时提供返回全部衣物的入口，不伪造收藏数据。
- 衣物在恢复当天选择后已归档、删除或被衣着偏好过滤时，必须自动移除。
- 页面不得自动调用去背服务；只有明确点击“生成贴纸”才可开始。
- 320px 以上视口不得横向溢出；按钮和可选衣物的触达区域至少 44px。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供独立的 `/stickers` 贴纸册页面，并从首页和穿搭日记提供入口。
- **FR-002**: 页面 MUST 提供“今日想穿”和“我的喜欢”两个来源视图。
- **FR-003**: 用户 MUST 能选择 1～8 件当前账号活跃衣物，并在贴纸板即时看到组合。
- **FR-004**: 当天选择 MUST 仅保存在当前设备，并在恢复时与服务端当前可见衣物重新取交集。
- **FR-005**: 贴纸板 MUST 优先显示已有透明图；普通原图 MUST 明确标记为待生成，不得伪装成透明贴纸。
- **FR-006**: 生成操作 MUST 只处理当前选中且缺少透明图的衣物，已有贴纸不得重复请求。
- **FR-007**: 服务端 MUST 重新鉴权、校验当前用户衣物归属，并复用既有专业去背、透明通道验证、自动裁边与私有 Storage 流程。
- **FR-008**: 页面 MUST 展示当前处理件数、成功或失败状态，并允许失败后重试。
- **FR-009**: 失败 MUST 保留原图和既有透明图，不得覆盖当前可用结果。
- **FR-010**: 白边、柔和阴影和纸张质感 MUST 复用衣拍即合既有四色视觉，不能照搬参考产品品牌或布局。
- **FR-011**: 页面 MUST NOT 恢复自由拖拽画布、分享卡片、虚拟模特、视频 Reel、转盘或统计功能。
- **FR-012**: 页面加载、筛选切换和选择衣物 MUST NOT 自动发起第三方去背请求。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可在 3 次以内点击完成“进入页面—选择衣物—开始生成”的主路径。
- **SC-002**: 100% 已有透明图的选中衣物无需新增请求即可显示为白边贴纸。
- **SC-003**: 100% 生成请求均由当前账号、当前衣物 ID 派生，客户端不能提交用户 ID 或 Storage 路径。
- **SC-004**: 生成失败时 100% 保留原图或旧透明图，且页面仍可继续选择和重试。
- **SC-005**: 390px 视口下无水平溢出，所有主要操作无遮挡且触达高度至少 44px。

## Assumptions

- “每天想穿”解释为按自然日保存在当前设备的临时选择，不新增跨设备日历或数据库表。
- 单次最多 8 件与当前穿搭复杂度边界一致，足够覆盖内搭、外套、下装、鞋与配饰。
- 既有百度专业去背和私有 `cutout_path` 是唯一图片处理底座；本阶段不恢复人工擦除/恢复编辑器。
- 参考图只用于理解“独立物体白边贴纸”和密集陈列氛围，不复制其品牌、配色、功能或版式。
