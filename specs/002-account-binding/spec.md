# Feature Specification: 邮箱绑定与会话恢复

**Feature Branch**: `002-account-binding`

**Created**: 2026-08-23

**Status**: Revised 2026-08-25

**Input**: 用户要求完成邮箱绑定，让匿名体验账号可以在不丢失衣橱数据的前提下跨设备恢复。

## User Scenarios & Testing

### User Story 1 - 匿名衣橱直接注册账号 (Priority: P1)

匿名用户在设置页一次填写邮箱和密码，无需打开验证邮件，现有匿名身份立即升级为可恢复账号，原有衣橱数据保持不变。

**Why this priority**: 这是从匿名体验升级为长期账号的核心价值，也是后续登录恢复的前提。

**Independent Test**: 在匿名会话中记录账号编号并创建一件测试衣物，直接注册后确认账号编号和衣物均未变化，再退出并用邮箱密码登录。

**Acceptance Scenarios**:

1. **Given** 用户处于匿名会话，**When** 提交有效且未被占用的邮箱、密码和二次确认，**Then** 当前用户立即成为邮箱账号且不发送验证邮件。
2. **Given** 注册成功，**When** 页面刷新，**Then** 原用户编号和已有衣橱数据保持不变并显示账号已保护。
3. **Given** 邮箱无效、已占用或密码不符合要求，**When** 用户提交，**Then** 页面显示通俗、可执行的错误提示且当前会话不受影响。

---

### User Story 2 - 已有账号直接登录与本地恢复 (Priority: P1)

已设置密码的邮箱账号可直接登录，不发送验证邮件；历史遗留的“已绑定邮箱但无密码”账号通过仅限本机、服务端密钥保护的一次性工具设置密码。

**Why this priority**: 只有可以重新登录，邮箱绑定才真正解决匿名身份易丢失的问题。

**Independent Test**: 完成绑定与密码设置后退出，再使用相同邮箱密码登录，确认用户编号和绑定前测试衣物一致。

**Acceptance Scenarios**:

1. **Given** 邮箱已绑定且当前会话有效，**When** 用户提交符合要求且两次一致的密码，**Then** 页面直接显示账号已受保护，不要求邮件确认。
2. **Given** 用户已设置密码，**When** 退出并使用正确邮箱密码登录，**Then** 恢复同一用户及全部既有数据。
3. **Given** 邮箱或密码错误，**When** 尝试登录，**Then** 不泄露账号是否存在，并显示可重试提示。

---

### User Story 3 - 清楚掌握账号状态 (Priority: P2)

用户可以在设置页看懂当前是匿名体验、等待验证、等待设置密码或已绑定状态，并在退出后明确选择登录或开始新的匿名体验。

**Why this priority**: 账号流程涉及邮件和多次跳转，清楚的状态可以避免误操作和数据丢失。

**Independent Test**: 分别进入匿名、验证后和已绑定状态，确认页面只展示当前可执行的下一步；退出后登录页不会自动创建匿名账号。

**Acceptance Scenarios**:

1. **Given** 当前是匿名账号，**When** 打开主页或设置，**Then** 展示注册与登录入口、邮箱密码输入和匿名身份丢失风险提示。
2. **Given** 当前是已绑定账号，**When** 打开设置，**Then** 展示脱敏邮箱、账号已可恢复和退出入口。
3. **Given** 用户已退出，**When** 打开登录页，**Then** 不自动创建匿名身份，并提供邮箱登录和主动开始新匿名体验两个选择。

### Edge Cases

- 旧验证链接失效、已使用或参数被篡改时，只提示改用邮箱密码登录，不再引导重发邮件。
- 用户提交已被占用的邮箱时，提示直接登录原账号，不创建或迁移业务数据。
- Supabase 仍开启 Confirm email 时，注册动作不得把等待邮件误报为注册完成。
- 断网或服务限流时，不清除当前会话，也不把失败状态误报为完成。
- 用户退出后选择新的匿名体验时，必须明确这是新身份，旧数据需通过原邮箱登录恢复。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 允许匿名用户从主页进入注册，并在设置页一次提交邮箱、密码与二次确认。
- **FR-002**: 系统 MUST 在 Supabase 关闭 Confirm email 后直接完成注册，不发送注册或密码设置验证邮件。
- **FR-003**: 绑定流程 MUST 保持原用户 ID，绑定前的资料、偏好、衣物与图片归属不得迁移或丢失。
- **FR-004**: 系统 MUST 在注册时设置至少 8 位密码并要求二次输入一致；已绑定会话缺少密码时允许在当前页面直接补设。
- **FR-005**: 系统 MUST 支持邮箱密码登录与退出，并在重新登录后恢复同一用户数据。
- **FR-006**: 登录页 MUST 阻止自动匿名初始化，并提供用户主动开始新匿名体验的入口和风险提示。
- **FR-007**: 设置页 MUST 根据账号状态只展示当前可执行操作，并展示脱敏邮箱而非完整敏感信息。
- **FR-008**: 系统 MUST 对重复邮箱、弱密码、凭据错误、限流和网络异常提供中文结果提示。
- **FR-009**: 所有账号变更 MUST 在服务端或受信任的认证客户端完成，不得暴露服务端密钥。
- **FR-010**: 本阶段 MUST 保留现有 RLS 与私有图片路径隔离能力。
- **FR-011**: 已绑定邮箱但无密码且原会话失效时，系统 MUST 仅提供本地交互式管理员工具；工具不得建立线上接口、回显密码或把服务端密钥暴露给浏览器。
- **FR-012**: 主页 MUST 为匿名访客提供清晰的“注册账号”和“登录”入口；已登录邮箱用户只展示账号设置入口。

### Key Entities

- **账号身份**: 当前用户的稳定身份，包含用户 ID、匿名状态、邮箱状态和可用登录方式。
- **本地恢复操作**: 由开发者在本机终端发起的一次性管理员密码设置，要求服务端密钥、隐藏密码输入和显式确认。
- **用户会话**: 浏览器当前持有的登录状态，可通过退出清除并通过邮箱密码恢复。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 用户可在一个表单内完成邮箱和密码注册，无需离开应用打开邮件。
- **SC-002**: 绑定前后及重新登录后用户 ID 100% 一致，绑定前测试衣物可完整访问。
- **SC-003**: 错误邮箱、弱密码、错误密码和失效链接均显示可理解的下一步提示。
- **SC-004**: 退出后的登录页不会自动生成匿名身份；主动匿名体验仍可在一次操作内开始。
- **SC-005**: 390px 移动端与桌面宽度均无横向溢出，键盘和读屏可完成核心流程。

## Assumptions

- 复用现有 Supabase Auth、SSR Cookie 会话、profiles 与 user_preferences，不新增业务账号表。
- 邮箱密码为本阶段唯一恢复方式；历史遗留无密码账号只允许通过本机管理员工具处理。常规忘记密码、换绑邮箱、OAuth、账号切换和删除账号仍不在本阶段。
- Supabase Email Provider 保持开启，但 Confirm email 关闭；正式公开上线前应重新评估无需邮箱所有权验证的账号冒用风险。
