# SDD-027 技术调研

## 决策 1：可信白名单使用官方 RSS，按日读取

- **采用**：`https://www.vogue.com/feed/rss` 与 `https://www.gq.com/feed/rss`。
- **理由**：2026-09-03 已以只读请求验证两者均返回 HTTP 200、`application/xml`，且条目带原始标题、链接和发布时间。白名单控制来源范围，RSS 只作为传输方式，不等同于无边界聚合。
- **边界**：仅解析 `title/link/pubDate`；不下载或展示来源图片、description、全文，不绕过付费墙。
- **替代方案**：运行时抓网页容易受页面结构和版权影响；人工静态目录无法满足每日新鲜度；均不采用。

## 决策 2：24 小时服务器缓存，不使用 Cron

- **采用**：Next.js `unstable_cache` 缓存已校验 RSS 结果与标题转写，`revalidate=86400`；缓存函数不访问 cookies 或个人画像。
- **理由**：产品只需要 App 内每日更新，访问触发缓存刷新即可；无需新增计划任务、服务端管理密钥或后台作业。
- **失败策略**：保留有效的历史来源缓存；首次无缓存时显示可解释空状态。2026-09-06 删除日期未独立核实的编辑后备，禁止编造新闻、发布日期或来源授权。

## 决策 3：规则先过滤，AI 只做可选中文转写

- **采用**：先用来源、URL、日期、关键词和 30 天主题指纹做校验；仅将通过校验的标题和内容 ID 发送到现有服务端 Responses API，`store:false` 与严格 JSON Schema，仅生成忠实中文标题。简述使用来源标题表述，不生成文章正文事实或购买结论。失败显示原题与明确标为“阅读提示”的通用建议，不能冒充新闻摘要。
- **理由**：真实性由来源元数据保证，AI 不决定事实；复用现有服务端密钥与传输，不增加客户端暴露。

## 决策 4：只持久化用户状态，不持久化外站内容

- **采用**：扩展 `user_preferences`，新增 `fashion_content_reads`；收尾增加 `fashion_topic_impressions`，用账号/主题唯一键与条件更新 RPC 保证 30 天内首次展示记录不被刷新覆盖。
- **理由**：内容可由白名单和每日缓存重建，持久化全文会增加版权与同步复杂度；用户状态必须跨设备保存并受 RLS 保护。
- **安全**：公开 schema 表启用 RLS，策略使用 `(select auth.uid()) = user_id`，并为 `user_id` 建索引；查询继续显式带当前用户过滤。

## 决策 5：个性化是可解释排序，不改变事实

- **采用**：先排除明确的衣着归属与冷热/雨天冲突，再用已有风格、近期日记/常用场景排序。天气通过现有有效位置解析，临时城市优先。关闭个性化后不查询衣橱、日记或天气，理由明确为按发布时间排序。
- **天气失败**：保留内容流但不使用天气信号，不生成虚假天气描述。
- **重复控制**：用来源 URL 生成稳定 ID，用归一化主题指纹将 30 天内同类报道压缩为一条。
