# Quickstart: 每日 3 套 AI 推荐

## 前置条件

1. `.env.local` 已配置两个 Supabase 公开变量。
2. `OPENAI_API_KEY` 可选；未配置时必须自动验收规则推荐。
3. Supabase 已应用本阶段迁移。
4. 当前匿名或邮箱会话已加载 24 件演示衣物。

## 自动检查

```bash
npm run check
npm run build
npm run verify:sdd-005
```

预期：

- 两组匿名会话只能读取和覆盖自己的当日批次。
- 同一会话连续 upsert 3 次后仍只有一行，最后一次输入生效。
- 每个测试批次恰好 3 套，批次内 ID 不重复。
- 无 `OPENAI_API_KEY` 时跳过真实 AI 基准，但规则和数据隔离仍通过。

## 浏览器核心流程

1. 打开 `/wardrobe`，确认演示衣橱为 24 件。
2. 打开 `/recommendations`，选择“通勤”和“实时天气”。
3. 点击生成，确认 15 秒内显示 3 套真实衣物原图卡片。
4. 检查每套名称、理由、标签和天气说明；同一单品不得出现在两套中。
5. 切换“约会”和“冷天测试”后重新生成，确认仍只有一个今日批次且卡片已替换。
6. 临时移除或禁用 `OPENAI_API_KEY`，重新生成并确认页面明确显示“规则推荐”。
7. 模拟天气请求失败，确认页面显示“模拟天气”，推荐仍可用。
8. 在 390px 宽度检查无水平滚动，生成中骨架不跳版，键盘可操作所有单选与按钮。

## 真实 AI 验收

- 模型输出只包含当前用户衣物 ID，不包含图片。
- 连续执行通勤、休闲、约会、正式四种场合，均得到 3 套合法方案。
- 记录每次来源与耗时；任何无效输出都必须自动转为规则结果，不向用户展示损坏 JSON。
