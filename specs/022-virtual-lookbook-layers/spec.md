# 功能规格：虚拟模特与分层穿搭

**功能目录**：`specs/022-virtual-lookbook-layers`  
**创建日期**：2026-08-31  
**状态**：本地开发完成，待回归补跑与部署  
**输入**：每日穿搭使用虚拟人物展示，并增加内搭、外套和配饰等更完整的层次。

## 用户场景与验收

### 用户故事 1：获得完整且可解释的分层穿搭（P1）

用户生成每日推荐时，除基础上装、下装和鞋外，还能在天气与库存允许时获得内搭、外套和 1～2 件配饰，并清楚看到每件衣物承担的角色。

**独立验收**：分别用冷天、温和天气和热天固定衣橱生成推荐；冷天可形成内搭与外套层次，热天不会强行叠穿，每套仍满足场景、归属、季节、完整性和跨套不重复规则。

1. **给定** 体感不高于 18°C 且库存充足，**当** 生成推荐，**那么** 系统优先为至少一套加入第二件上装作为内搭层次。
2. **给定** 体感不高于 8°C，**当** 生成推荐，**那么** 每套继续必须包含外套。
3. **给定** 体感不低于 27°C，**当** 生成推荐，**那么** 系统不得为了复杂度强行加入冬季外套或第二件厚上装。
4. **给定** 配饰库存合法且不影响三套完整性，**当** 生成推荐，**那么** 每套最多使用 2 件配饰。

### 用户故事 2：生成虚拟模特效果图（P1）

用户可在任一推荐卡上按需生成一张虚拟模特 Lookbook，直观看到整套的比例和层次，同时继续查看真实衣物图核对实际单品。

**独立验收**：在一套有效推荐上点击“生成虚拟模特效果图”；成功后页面显示效果图、参考说明和原始衣物清单，刷新后仍可读取；未点击的另外两套不产生图像调用。

1. **给定** 当前推荐属于登录账号，**当** 用户为某一套生成效果图，**那么** 系统只使用该套衣物属性、天气、场景和衣着偏好生成一张图。
2. **给定** 效果图生成成功，**当** 页面重新读取推荐，**那么** 显示缓存图，不重复付费生成。
3. **给定** 用户替换了该套任一衣物，**当** 保存替换，**那么** 旧效果图立即失效，用户可按新搭配重新生成。
4. **给定** 图像服务失败、超时、限流或未配置，**当** 用户点击生成，**那么** 推荐与真实衣物图保持可用，并给出可重试说明。

### 用户故事 3：清楚区分效果参考与真实衣物（P2）

用户不会把生成图误认为精确试穿结果，能够随时回到真实单品核对颜色、版型和材质。

**独立验收**：查看有图和无图两种推荐卡；均能看到“效果参考”说明、真实单品和层次标签，390px 下无横向溢出。

1. **给定** 效果图存在，**那么** 页面必须说明它用于展示搭配比例，实际颜色和版型以衣物实拍为准。
2. **给定** 效果图不存在，**那么** 页面使用固定无身份虚拟模特作为视觉引导，但不遮挡真实衣物拼图。
3. **给定** 用户启用减少动态，**那么** 新增卡片和生成状态不依赖持续动画表达信息。

## 边界与异常

- 本阶段是 Lookbook 视觉参考，不是用户本人照片试穿、换脸、体型复刻或尺码预测。
- 动态效果图按单套点击生成，不在每次生成推荐时自动调用 3 次图像模型。
- 效果图不得引入清单外的明显服装角色；生成结果可能存在视觉误差，因此真实衣物图始终保留。
- 图像仅保存在当前账号私有空间，路径必须以当前账号 ID 开头，读取使用短期签名地址。
- AI 图像失败不得影响推荐保存、换件、收藏、日记或利用率。
- 配饰最多 2 件；单套总衣物最多 7 件；不得为了数量突破天气、场景、衣着归属或跨套不重复硬规则。

## 功能需求

- **FR-001**：推荐契约必须支持每套 3～7 件衣物，并为每件衣物派生唯一层次角色。
- **FR-002**：层次角色必须覆盖内搭、主上装、外套、下装、连衣裙、鞋和配饰；不适用的角色可缺省。
- **FR-003**：一套最多包含 2 件上装、1 件外套、1 件下装或 1 件连衣裙、1 双鞋和 2 件配饰。
- **FR-004**：AI、规则降级和最终校验必须共用单套数量、类别、温度和跨套不重复规则。
- **FR-005**：体感不高于 18°C 且合法库存充足时，规则降级必须尝试增加内搭；体感不低于 27°C 时不得强制叠穿。
- **FR-006**：推荐卡必须以中文展示衣物角色，并继续提供真实衣物图、换件、收藏和日记入口。
- **FR-007**：每套必须提供独立的“生成虚拟模特效果图”操作，未操作的套装不得触发图像调用。
- **FR-008**：图像生成操作必须在服务端重新验证当前用户、推荐所有权、套装位置和当前衣物合法性。
- **FR-009**：图像提示必须使用当前套装的层次、颜色、材质、风格、天气、场景和衣着偏好，不得包含用户个人照片或账号敏感信息。
- **FR-010**：生成成功后必须把图片写入当前账号私有空间，并把路径、模型和生成时间写回当前套装快照。
- **FR-011**：页面读取效果图时必须验证路径属于当前账号并使用限时访问地址。
- **FR-012**：替换套装衣物时必须清除该套效果图元数据，避免旧图继续展示。
- **FR-013**：图像未配置、超时、限流、内容拦截或保存失败时必须返回明确错误，不得删除或覆盖当前推荐。
- **FR-014**：固定虚拟模特和动态效果图都必须标注“仅供搭配参考，实际颜色与版型以衣物实拍为准”。
- **FR-015**：新增页面必须适配 390px、键盘焦点、减少动态和当前冷白银灰视觉系统。

## 关键实体

- **分层穿搭**：现有推荐套装的标准化视图，由衣物 ID、派生角色、文字说明和可选效果图元数据组成。
- **衣物角色**：一件衣物在当前套装中的用途，不改变衣物本身分类。
- **Lookbook 效果图**：某次推荐某一套的虚拟模特图片，包含私有路径、生成模型和生成时间。

## 成功标准

- **SC-001**：固定冷天样本的三套均通过现有硬约束，且至少一套在库存允许时包含内搭、主上装、外套、下装、鞋的五层结构。
- **SC-002**：固定热天样本 100% 不出现冬季外套或强制第二件厚上装。
- **SC-003**：每套派生角色与衣物 ID 一一对应，重复角色和超量类别为 0。
- **SC-004**：用户可在一次操作内生成单套效果图；成功后刷新读取不产生新模型请求。
- **SC-005**：图像服务失败时，原推荐、真实衣物、换件、收藏和日记仍可正常使用。
- **SC-006**：跨账号读取、写入或签名他人效果图的成功数为 0。
- **SC-007**：390px 页面无水平溢出，效果图、参考说明和真实衣物清单在 1 分钟内可理解。

## 假设与明确不做

- 复用现有账号、推荐 JSON 快照和私有 `wardrobe-images` 空间，不新增数据库表。
- 图像按需生成并缓存，默认使用当前 OpenAI 图像模型；图像功能可独立降级。
- 固定虚拟模特为无身份、弱化面部的棚拍形象，不对应真实用户。
- 不做用户照片上传、真人换装、面部一致性、身体测量、尺码推荐、视频或多角度渲染。
