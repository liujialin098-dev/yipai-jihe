# 实现计划

1. 保持确认入库API不变，客户端在成功响应后排入独立串行队列，不阻塞下一件入库。
2. 请求既有POST `/api/stickers/items/:id`，同源Cookie、60秒客户端超时；只接受created/reused与HTTPS图片URL。
3. 队列同itemId去重，完成图片缓存于当前工作区状态；failed只允许用户主动重试。卸载停止后续请求与状态更新，已发出的服务端处理不回滚。
4. 队列状态在卡片内展示；仅就绪才使用GarmentSticker，其他状态保留原图。提示保持简洁，重试至少44px，日夜复用当前token，不另造设计系统。
5. 全批重置在贴纸排队/制作期间禁用，终态后可继续添加。所有导航关闭预取，避免保存前缓存旧贴纸页。
6. 固定请求与队列测试、实际组件渲染、check/build、033/037回归；浏览器验证添加页与真实可用配置，不修改用户密钥。

技术边界：只接既有服务，无Supabase schema/API语法变化；当前官方Storage文档确认私有对象仍依赖RLS与账号归属，不改变权限策略。
