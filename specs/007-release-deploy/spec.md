# Feature Specification: 全链路加固与受控上线

**Feature Branch**: `007-release-deploy`

**Created**: 2026-08-24

**Status**: Draft

**Input**: 在 SDD-001、003～006 已完成的匿名 MVP 上完成全链路回归、发布文档、配置核对和受控 Vercel Preview，形成 5 分钟可复现的评审版本。

## Clarifications

### Session 2026-08-24

- Q: 本阶段是否发布到正式生产域名？ → A: 不发布；使用受 Vercel Authentication 保护的独立 Preview 作为受控评审链接。
- Q: 密码设置与重新登录是否阻塞 P0 评审？ → A: 不阻塞；继续作为 SDD-002 的集中人工调试项，并在评审说明中明确排除。
- Q: 是否在本阶段增加新业务功能或数据库表？ → A: 不增加；只修复阻塞核心演示的问题，并以现有迁移作为数据库唯一事实来源。
- Q: 真实 AI 因本地网络不可达时如何验收？ → A: 保留已完成的线上识别证据；本阶段验证服务端配置、降级链路和 Preview 构建，线上真实推荐与密码一起集中调试。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 5 分钟完成核心演示 (Priority: P1)

作为评审者，我可以从一个新匿名会话开始，在 5 分钟内完成演示衣橱、添加衣物、每日三套、换件和收藏的核心路径，并在刷新后看到数据保持。

**Why this priority**: 受控评审版的首要价值是让核心闭环可被稳定、快速地复现。

**Independent Test**: 新建匿名会话，按发布 quickstart 依次完成演示数据、推荐、换件、收藏与偏好，记录每一步结果和总用时。

**Acceptance Scenarios**:

1. **Given** 新匿名会话，**When** 一键加载演示衣橱，**Then** 得到不少于 20 件安全演示衣物且重复加载不重复。
2. **Given** 衣橱已准备，**When** 生成今日推荐并完成一次换件和收藏，**Then** 三套仍完整、刷新后保持且收藏页可回看。
3. **Given** AI 或天气服务不可用，**When** 执行核心路径，**Then** 页面在可理解提示下使用模拟天气或规则方案继续完成演示。

---

### User Story 2 - 安全且可复现的发布验收 (Priority: P2)

作为项目维护者，我可以运行一组固定命令核对类型、构建、环境变量边界、迁移完整性和用户隔离，不依赖记忆判断版本是否可发布。

**Why this priority**: 发布证据必须可重复，且不能因匿名体验而放松用户所有权和密钥边界。

**Independent Test**: 运行发布审计、生产构建和双匿名会话脚本，确认无公开服务端密钥、迁移齐全、跨用户访问被拒绝。

**Acceptance Scenarios**:

1. **Given** 当前代码，**When** 运行发布质量命令，**Then** 格式、lint、类型和生产构建全部通过。
2. **Given** 两个匿名会话，**When** 尝试读取或写入对方资料、衣物、推荐、收藏和反馈，**Then** RLS 拒绝跨用户访问。
3. **Given** 发布配置，**When** 执行静态审计，**Then** 浏览器只暴露两个 Supabase 公开变量，OpenAI 与服务端秘密不使用 `NEXT_PUBLIC_` 前缀。

---

### User Story 3 - 获取清晰的评审入口与限制说明 (Priority: P3)

作为评审者或后续开发者，我可以从 README 和阶段 quickstart 找到受控链接、环境配置、演示步骤、验证命令、数据库迁移和已知限制。

**Why this priority**: 清晰交付可以减少口头解释，并避免把暂缓能力误判为缺陷。

**Independent Test**: 仅阅读 README 与 quickstart，在没有额外上下文的情况下完成本地启动或理解 Preview 评审方式。

**Acceptance Scenarios**:

1. **Given** 新开发环境，**When** 阅读 README，**Then** 可以复制环境模板、安装依赖、运行迁移和启动应用。
2. **Given** 受控 Preview，**When** 阅读评审步骤，**Then** 可以在 5 分钟路径中区分核心能力、降级行为和暂缓项。
3. **Given** 阶段完成，**When** 查看 `progress.md`，**Then** 可找到最终链接、部署 ID、验收证据、限制和提交记录。

### Edge Cases

- 新会话因匿名登录限流失败时显示可重试状态，不进入循环创建会话。
- 演示数据为空、已部分存在或重复加载时，核心路径仍有明确下一步。
- 没有合法替换候选时保留原方案并改选其他单品，不把无候选误报为系统故障。
- OpenAI 额度、连接或输出失败时，AI 入库允许手工填写，推荐使用规则降级。
- Preview 受保护时不得创建或提交绕过保护的长期令牌；评审者使用团队授权访问。
- 清除站点数据后会生成新匿名身份，旧数据不能被新身份读取。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供可在 5 分钟内完成的匿名核心演示步骤，覆盖演示衣橱、入库、三套推荐、换件、收藏和偏好。
- **FR-002**: 系统 MUST 为核心页面提供加载、空数据、错误、超时、降级或重试反馈，不得出现无说明死路。
- **FR-003**: 发布验收 MUST 覆盖 390px 首页、衣橱、添加、推荐、收藏、设置和偏好页，并确认无水平滚动。
- **FR-004**: 发布验收 MUST 使用至少两个匿名会话验证资料、衣物、Storage、推荐、收藏和反馈隔离。
- **FR-005**: 系统 MUST 验证清除站点数据后得到新身份，且新身份无法访问旧身份业务数据。
- **FR-006**: 仓库 MUST 提供发布审计命令，核对必需脚本、迁移、环境变量模板、核心路由和文档。
- **FR-007**: README MUST 说明产品范围、技术栈、本地启动、环境变量、迁移、验证、演示路径、部署和已知限制。
- **FR-008**: 数据库结构 MUST 仅由 `supabase/migrations/` 重放，不提供与迁移漂移的第二份建表 SQL。
- **FR-009**: Vercel Preview MUST 构建成功并记录链接、部署 ID、保护状态和环境配置边界。
- **FR-010**: 浏览器代码 MUST NOT 读取 `OPENAI_API_KEY`、`SECRET_KEY` 或其他服务端秘密。
- **FR-011**: 本阶段 MUST NOT 发布正式生产域名、创建保护绕过令牌或扩大到自动抠图、日记、虚拟试穿。
- **FR-012**: 邮箱密码设置、退出和重新登录 MUST 继续记录为 SDD-002 待人工集中调试，不得伪造通过结果。

## Success Criteria *(mandatory)*

- **SC-001**: `npm run check`、`npm run build`、`npm run verify:sdd-007` 全部通过。
- **SC-002**: 390px 核心路由无水平溢出、页面错误覆盖层或损坏图片。
- **SC-003**: 双匿名会话的跨用户读写测试全部被拒绝，测试记录可清理。
- **SC-004**: 受控 Preview 状态为 READY，14 个应用页面/接口路由完成生产构建。
- **SC-005**: README 与 quickstart 能独立说明 5 分钟演示、配置和暂缓范围。
- **SC-006**: `progress.md`、`AGENTS.md` 和 SDD 任务状态与实际提交一致。

## Assumptions

- 现有 Vercel 项目和 Supabase 项目继续复用，不创建会产生费用的新项目或分支。
- Preview 保护由现有团队登录管理，本阶段不改变访问策略。
- SDD-004 已记录的 10/10 真实识别结果有效，不重复消耗额度；规则推荐与手工入库作为本轮离线降级验收。
- 当前 P0 以匿名体验为默认入口，账号恢复能力不是核心演示依赖。
