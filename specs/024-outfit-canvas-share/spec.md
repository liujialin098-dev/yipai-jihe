# Feature Specification: 穿搭画布与分享卡片

**Feature Branch**: `024-outfit-canvas-share`

**Created**: 2026-09-01

**Status**: 已完成，待部署

**Input**: User description: "模仿 Whering 的核心体验，用抠出的真实衣物自由排布并生成可分享穿搭卡片；穿搭不再使用模特，只展示衣物。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 用真实衣物创建自由画布 (Priority: P1)

用户从每日推荐中的任意一套搭配进入穿搭画布，看到该套真实衣物而不是人物或重新生成的服装。用户可以触摸拖动衣物、缩放、旋转、调整前后层级，并随时恢复推荐初始排布。

**Why this priority**: 衣物准确性和可控排布是本功能的核心价值，先解决 AI 模特图改款、改色和不可信的问题。

**Independent Test**: 从一套包含 3-7 件衣物的推荐进入画布，逐件核对 ID 和图片，完成拖动、缩放、旋转、层级调整与重置后，页面没有人物图片，也没有新的图像生成请求。

**Acceptance Scenarios**:

1. **Given** 用户有一套有效推荐，**When** 点击“编辑穿搭卡片”，**Then** 画布载入该套全部真实衣物并生成不重叠的初始排布。
2. **Given** 用户选中一件衣物，**When** 拖动、缩放、旋转或调整层级，**Then** 只有该衣物改变，其他衣物保持原位置。
3. **Given** 用户对布局不满意，**When** 点击恢复排布，**Then** 画布回到当前搭配的稳定初始布局。

---

### User Story 2 - 在设备本地整理衣物背景 (Priority: P1)

用户可以对画布中的衣物执行本地抠图。系统在浏览器内识别图片边缘的近似纯色背景，生成透明 PNG 并保存为该衣物的派生图；原图始终保留。复杂背景无法可靠处理时，用户可以继续使用原图，不阻塞画布和分享。

**Why this priority**: 透明衣物才能在多彩画布上自然排布，同时本地处理避免新增第三方图片传输、API 费用和服务依赖。

**Independent Test**: 使用纯色棚拍、透明图、复杂生活照三类样本，确认前两类可生成透明背景，复杂图失败时仍保留原图；重新进入画布后已保存的抠图可复用。

**Acceptance Scenarios**:

1. **Given** 衣物图片背景近似纯色，**When** 用户执行本地抠图，**Then** 生成透明 PNG，原始衣物记录和原图不被覆盖。
2. **Given** 衣物已有抠图，**When** 用户再次进入画布，**Then** 优先显示已保存的透明图，不重复处理。
3. **Given** 图片背景复杂或处理失败，**When** 用户继续编辑，**Then** 系统清楚提示并继续使用原图。

---

### User Story 3 - 保存并分享穿搭卡片 (Priority: P2)

用户可以给穿搭命名、选择卡片底色、保存当前布局，并导出一张只包含品牌标识、标题和真实衣物排布的高清图片。支持系统分享的设备直接调起分享面板，不支持时下载 PNG。

**Why this priority**: 可保存和分享让画布从一次性编辑变成可回顾、可传播的个人穿搭成果。

**Independent Test**: 保存一张修改过的卡片，刷新后布局一致；导出 PNG 后逐件核对位置、缩放、旋转和层级与画布一致，并确认图片中没有模特或私人邮箱等账号信息。

**Acceptance Scenarios**:

1. **Given** 用户完成排布，**When** 保存卡片，**Then** 当前用户下生成或更新一条穿搭画布记录。
2. **Given** 已保存画布，**When** 用户刷新或再次打开，**Then** 标题、背景和全部衣物变换保持一致。
3. **Given** 浏览器支持文件分享，**When** 用户点击分享，**Then** 调起系统分享面板；不支持时下载 PNG。

---

### User Story 4 - 手机端稳定编辑 (Priority: P3)

用户在 390px 手机宽度下可以单指拖动、通过明确控件缩放和旋转，不会误触页面滚动或看不到操作按钮；减少动态设置下仍可完整使用。

**Why this priority**: 项目是移动端优先产品，触摸稳定性决定画布是否真正可用。

**Independent Test**: 在 390px 视口完成进入、选择、拖动、缩放、旋转、保存和导出全流程，页面无横向溢出，控件可键盘聚焦并具备可读标签。

**Acceptance Scenarios**:

1. **Given** 用户在手机上拖动衣物，**When** 指针移出衣物范围，**Then** 拖动仍连续并在抬手时保存最终位置。
2. **Given** 用户启用减少动态，**When** 使用画布，**Then** 自动显现和弹性反馈停止，但编辑能力不受影响。

### Edge Cases

- 推荐记录不存在、已过期或不属于当前用户时，不创建空白伪搭配，返回推荐页并说明原因。
- 衣物被归档、删除或不属于当前用户时，从画布输入中排除，不接受客户端伪造的衣物 ID。
- 少于 2 件有效衣物时不保存为穿搭卡片，并引导用户返回衣橱或推荐页。
- 单件图片加载失败时显示名称占位，其他衣物仍可编辑和导出。
- 导出图片时签名地址失效，系统重新载入当前用户图片；仍失败时给出可重试提示，不导出残缺卡片。
- 画布最多接受 8 件衣物，超出部分必须先由用户移除。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许用户从当前用户拥有的推荐搭配进入穿搭画布，且只读取该搭配真实衣物。
- **FR-002**: 画布 MUST 只展示衣物排布，不展示人物、人体轮廓或 AI 模特图。
- **FR-003**: 用户 MUST 能拖动衣物，并通过明确控件缩放、旋转、前移、后移、移除和恢复初始排布。
- **FR-004**: 系统 MUST 将衣物位置保存为画布宽高无关的相对坐标，使不同手机宽度下布局保持一致。
- **FR-005**: 系统 MUST 在浏览器本地处理近似纯色背景，生成透明 PNG；处理过程不得新增向第三方服务上传衣物图片。
- **FR-006**: 系统 MUST 将抠图保存为原图之外的派生文件，并允许失败时继续使用原图。
- **FR-007**: 系统 MUST 优先复用已有抠图，不得覆盖或删除原始衣物图片。
- **FR-008**: 用户 MUST 能为卡片设置 1-30 个字符的名称，并从预设背景中选择一种。
- **FR-009**: 系统 MUST 保存当前用户的穿搭卡片，并保证其他账号不能读取、修改或删除。
- **FR-010**: 每张卡片 MUST 包含 2-8 件当前用户衣物、每件衣物的相对位置、缩放、旋转和层级。
- **FR-011**: 系统 MUST 能按当前画布生成至少 1080px 宽的 PNG，包含衣拍即合标识、卡片名称和衣物排布，不包含邮箱、账号编号或天气位置。
- **FR-012**: 支持系统文件分享的浏览器 MUST 调起系统分享；其他浏览器 MUST 下载 PNG。
- **FR-013**: 画布 MUST 在 390px 视口无水平溢出，触摸拖动与页面滚动边界清楚，并支持键盘聚焦与可读操作名称。
- **FR-014**: 系统 MUST 提供加载、抠图中、保存中、导出中、空状态和失败重试状态。
- **FR-015**: 默认推荐卡 MUST 以衣物画布入口替代人物预览主路径；现有 AI 模特图不再作为默认推荐视觉。

### Key Entities

- **穿搭画布**：一名用户保存的一张穿搭卡片，包含名称、背景主题、来源推荐和更新时间。
- **画布衣物**：穿搭画布中的真实衣物引用，以及相对坐标、缩放、旋转和层级。
- **衣物抠图**：由衣物原图在本地生成的透明派生图片，绑定原衣物但不覆盖原图。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可以在 90 秒内从任意一套推荐完成首次排布、保存和导出。
- **SC-002**: 保存并刷新后，全部衣物的位置、缩放、旋转和层级与保存前一致，核对准确率达到 100%。
- **SC-003**: 近似纯色背景固定样本的衣物主体保留率达到 90% 以上，背景四角透明；复杂背景失败时 100% 保留原图可用路径。
- **SC-004**: 两个测试账号之间的画布记录、抠图路径和图片读取全部被拒绝。
- **SC-005**: 390px 视口下完整编辑流程无横向溢出，拖动期间不触发意外页面滚动。
- **SC-006**: 导出的 PNG 至少 1080px 宽，2-8 件衣物全部出现，且不包含人物图片或账号私密信息。

## Assumptions

- 首版本地抠图面向纯色或接近纯色背景的衣物照片，不承诺复杂生活照达到专业云抠图质量。
- 原图仍是衣物真实性依据，抠图仅是可逆的展示派生物。
- 穿搭卡片先作为当前账号私有成果保存；分享的是导出图片，不建立公开个人主页或公开链接。
- 初始画布从每日推荐进入，手工跨衣橱选衣创建留给后续增量。
- 复用现有 Supabase 私有图片桶和账号隔离规则，不新增公开图片桶。
