# 快速验收：首次账号入口

## 前置条件

- `.env.local` 已配置两个 Supabase 公开变量。
- Supabase Auth 已启用 Email 与 Anonymous Sign-Ins，并关闭 Confirm email。
- 不需要 `SECRET_KEY`，不得把个人密码写入测试脚本或日志。

## 自动检查

```powershell
npm run check
npm run build
npm run verify:sdd-016
```

预期：静态检查和生产构建通过；验证脚本确认首页分流、禁止自动匿名、直接注册有效会话、登录恢复、退出及双用户隔离，并清理脚本创建的测试数据或明确记录认证用户清理限制。

## 390px 浏览器验收

1. 使用全新浏览器上下文打开 `/`。
2. 确认只看到“登录 / 注册 / 体验使用”，没有顶部账号状态、底部 Dock、衣橱数量或推荐内容。
3. 停留并刷新三次，确认未创建体验用户、页面不闪现应用首页且无横向溢出。
4. 切换登录与注册，确认字段、图标、错误位和按钮不重叠，键盘焦点清晰。
5. 使用安全合成测试邮箱完成注册，确认不打开邮箱、不点击链接即可进入 App。
6. 退出后确认返回统一入口；使用刚才的邮箱密码登录，确认恢复同一账号。
7. 再用全新浏览器上下文点击“体验使用”，确认明确提示数据限制后进入 App。
8. 检查浏览器控制台无错误覆盖层，所有等待按钮不会重复提交。

## 回归

- 体验账号在设置页注册后用户 ID 与已有衣物保持不变。
- 直接访问 `/wardrobe`、`/recommendations` 或 `/settings` 的无会话访问者回到统一入口，不自动创建体验身份。
- 已登录用户打开 `/` 仍看到原首页、顶部状态与底部 Dock。
