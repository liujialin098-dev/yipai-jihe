# Quickstart: IP 天气城市建议验收

## 前置条件

- `.env.local` 已配置当前 Supabase 公开连接变量。
- 本地开发没有 Vercel IP 头属于正常情况；IP 建议的固定样本由独立脚本验证。
- 使用合成测试账号和城市，不输入真实个人凭据或地址。

## 自动验收

```powershell
npm run check
npm run build
npm run verify:sdd-019
npm run verify:sdd-012
npm run verify:sdd-013
npm run verify:sdd-018
```

预期：

- 编码城市、缺失字段、非中国国家、无效坐标、同城距离和跨城距离固定样本全部通过。
- 临时 Cookie 只对匹配用户生效，损坏值和另一用户值被忽略。
- 推荐读取与生成均接入当前有效城市，无默认武汉/北京或模拟天气。
- 武汉/上海双账号 RLS 和真实今天/明天天气回归保持通过。

## 390px 浏览器验收

1. 用测试账号登录，把常用城市保存为武汉。
2. 在可控制请求头的 Preview/Production 请求中模拟杭州 IP；确认推荐页只出现建议，没有自动切换。
3. 点击“本次使用”，确认当前城市显示杭州、常用城市仍为武汉，旧推荐消失。
4. 生成今天和明天推荐，确认天气城市为杭州且来源为真实 Open-Meteo。
5. 点击“恢复武汉”，确认临时状态消失、旧杭州推荐消失。
6. 再次模拟杭州并点击“设为常用城市”，刷新后确认常用城市为杭州。
7. 移除定位头或模拟 VPN 非中国出口，确认页面不显示错误定位提示且手动城市入口仍可用。
8. 检查页面 `scrollWidth <= innerWidth`，按钮不重叠，控制台无 error。

## 隐私与失败边界

- 网络请求中不新增客户端 IP 上报或定位接口。
- 仓库、日志、Cookie 和数据库不保存原始 IP 地址。
- IP 仅为城市级近似建议，确认动作仍重新解析城市。
- 定位不可用时继续使用用户选择城市；天气不可用时停止生成，不编造结果。
