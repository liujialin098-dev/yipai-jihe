# Quickstart: SDD-012 独立验收

## 前置条件

- `.env.local` 已配置当前 Supabase 项目的两个公开变量。
- Supabase 已应用本阶段迁移。
- 本地运行 `npm run dev`。

## 质量命令

```powershell
npm run check
npm run build
npm run verify:sdd-012
```

## 场景一：武汉实时天气

1. 使用测试账号进入 `/settings/preferences`。
2. 城市填写“武汉”，衣着偏好选择“男装”，保存。
3. 返回 `/settings`，确认摘要显示“武汉”“男装”。
4. 进入 `/recommendations`，选择实时天气并生成。

预期：天气卡显示武汉；服务正常时标记实时天气，失败时标记武汉的模拟天气；任何情况下不显示北京。

## 场景二：男装过滤可逆

1. 在 `/wardrobe` 加载 24 件演示衣物。
2. 保存男装偏好并返回衣橱。
3. 检查衣橱、首页预览和新生成的三套推荐。
4. 将衣着偏好改回不限。

预期：男装时四件演示连衣裙均不显示且不进入推荐；中性上装、下装、外套、鞋和配饰正常保留；切回不限后裙装重新出现，数据库记录数不变。

## 场景三：错误与旧结果

1. 先生成一个当日方案，再将城市从武汉改为上海。
2. 输入不存在的城市并尝试保存。
3. 在天气服务不可用条件下生成。

预期：城市改变后旧方案不再显示；无效城市不覆盖上海；天气失败显示同一城市的模拟来源。

## 场景四：账号隔离

运行 `npm run verify:sdd-012`。脚本创建两个非敏感匿名测试账号，验证：

- A、B 可以分别保存不同城市和衣着偏好。
- A 无法读取或修改 B 的偏好。
- 男装过滤不删除任何衣物记录。
- 演示裙装归属为女装，中性单品归属不变。
- 测试结束自动清理测试衣物和账号数据。

## 场景五：按钮动效回归

在 390px 与桌面宽度分别检查设置、登录、衣橱和推荐页的黑色按钮。

预期：悬停、键盘焦点和按压时没有白色条带掠过文字；只保留柔和径向反馈和轻微按压景深；启用减少动态效果后无自动动画。
