# Quickstart: 推荐页城市切换与连续入库

## 前置条件

1. `.env.local` 已配置当前 Supabase 与 OpenAI 服务端变量。
2. Supabase 项目可访问，当前账号已有衣橱数据。
3. 使用 390px 浏览器视口完成移动端人工验收。

## 自动门禁

```bash
npm run check
npm run build
npm run verify:sdd-018
npm run verify:sdd-007
npm run verify:sdd-015
npm run verify:sdd-012
npm run verify:sdd-013
```

## 场景一：连续两批添加

1. 打开 `/wardrobe/new`，选择 10 张固定测试图片。
2. 完成识别和 10 件确认入库。
3. 确认底部出现“继续添加衣服”和“查看衣橱”。
4. 点击“继续添加衣服”。
5. 确认队列为空，文件选择恢复可用；重新选择下一批图片。
6. 打开衣橱，确认第一批记录仍在且没有重复。

## 场景二：推荐页切换城市

1. 账号当前城市保持武汉，打开 `/recommendations`。
2. 确认天气区说明“使用账号保存城市，不按 IP 自动切换”。
3. 点击“选择城市”，输入“上海”并保存。
4. 确认显示保存成功，旧武汉推荐消失。
5. 生成今天和明天搭配，确认两者都显示上海及真实 Open-Meteo 来源。
6. 刷新页面并重新登录，确认城市仍为上海。

## 场景三：失败与隔离

1. 输入不存在或过短的城市，确认原城市不变。
2. 使用双匿名测试账号分别保存武汉和上海，确认不能修改或读取对方偏好。
3. 模拟天气服务失败，确认停止生成且不显示模拟天气或旧城市结果。

## 预期结果

- 满批完成后下一批入口不再被 10 件上限阻塞。
- 城市来源可解释、可主动修改、跨登录保留。
- 城市变化后所有新推荐只使用新城市真实天气。
- 页面无水平溢出、无控制台 error，按钮保持现有动效与视觉 token。
