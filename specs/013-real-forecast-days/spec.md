# Feature Specification: 今日与明日真实天气搭配

**Feature Branch**: `master`

**Created**: 2026-08-25

**Status**: Draft

**Input**: User description: "增加明日天气，可以选择根据今天还是明天的天气进行搭配，天气必须是实际的天气，不允许乱编。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 选择今天或明天生成搭配 (Priority: P1)

用户进入推荐页后，可以在“今天”和“明天”之间切换，并为所选日期生成三套搭配。两个日期各自保存结果，互不覆盖。

**Why this priority**: 用户需要提前准备次日穿着，同时不能破坏已经生成的今日方案。

**Independent Test**: 先为今天生成方案，再切换到明天生成方案；两个日期均能重新打开并看到各自的天气和三套搭配。

**Acceptance Scenarios**:

1. **Given** 用户位于推荐页，**When** 切换“今天 / 明天”，**Then** 标题、日期、天气说明、按钮和结果区域同步显示所选日期。
2. **Given** 今天已有推荐，**When** 用户为明天生成推荐，**Then** 明日结果保存到明日日期，今日结果不被覆盖。
3. **Given** 今天和明天均有推荐，**When** 用户往返切换，**Then** 页面分别读取对应日期的方案。

---

### User Story 2 - 只使用真实天气数据 (Priority: P1)

今天的搭配使用账号城市的当前天气，明天的搭配使用同一城市的明日公开预报。系统明确显示城市、日期和真实来源，不再向普通用户提供模拟天气。

**Why this priority**: 天气直接影响衣物厚薄和防雨判断，虚构或静默降级会让推荐失去可信度。

**Independent Test**: 账号城市设为武汉，分别打开今天与明天并生成；天气数据与公开天气接口相同，来源均为真实天气服务。

**Acceptance Scenarios**:

1. **Given** 账号已保存武汉，**When** 为今天生成，**Then** 系统读取武汉当前温度、体感温度和天气代码并标为真实的实时天气。
2. **Given** 账号已保存武汉，**When** 为明天生成，**Then** 系统读取武汉明日预报日期、最低温度、最低体感温度和天气代码并标为真实的明日预报。
3. **Given** 天气服务超时、限流、报错或返回缺失数据，**When** 用户生成，**Then** 系统停止本次生成并提示真实天气暂时无法获取，不保存模拟天气或新推荐。
4. **Given** 账号未保存城市，**When** 用户尝试生成，**Then** 系统引导先设置常用城市，不使用北京或其他默认城市。

### Edge Cases

- 明日预报数组没有与账号时区下明日日期完全匹配的记录时，视为天气不可用，不取其他日期代替。
- 当前天气或明日预报的温度、体感温度、天气代码超出合理范围时，视为无效响应。
- 旧记录使用模拟天气时，不作为当前有效方案展示，用户需使用真实天气重新生成。
- 用户快速连续提交同一日期时，仍按账号和目标日期覆盖同一批次；今天与明天各最多一条。
- 跨过账号时区午夜后，“今天 / 明天”日期随账号城市时区重新计算。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 推荐页 MUST 提供“今天”和“明天”两个清晰可切换的日期选项，默认选择今天。
- **FR-002**: 系统 MUST 使用账号保存城市的时区计算今天与明天的自然日期。
- **FR-003**: 今天 MUST 使用账号城市的当前天气；明天 MUST 使用同一城市返回的明日预报。
- **FR-004**: 系统 MUST 校验明日预报日期与目标日期完全一致，不得使用其他日期或固定默认值冒充。
- **FR-005**: 系统 MUST 在页面显示城市、目标日期、天气概况、体感信息和真实天气服务来源。
- **FR-006**: 天气服务失败或响应无效时，系统 MUST 停止生成并给出可重试提示，不得创建模拟天气快照或保存新推荐。
- **FR-007**: 普通推荐界面 MUST 移除温和、热天、冷天和雨天等模拟天气选项。
- **FR-008**: 同一账号同一目标日期 MUST 最多保存一个推荐批次；今天与明天 MUST 分别保存并读取。
- **FR-009**: 目标日期、标题、生成按钮、天气摘要和推荐结果 MUST 保持一致，不能把明日结果标成今日。
- **FR-010**: 旧的模拟天气批次 MUST 不再作为当前有效结果展示。
- **FR-011**: 真实天气请求、账号读取和推荐写入 MUST 继续在服务端完成，并沿用当前账号所有权隔离。
- **FR-012**: AI 推荐失败仍 MAY 使用既有规则推荐，但前提是本次真实天气已成功获取；天气本身不得规则降级或模拟。

### Key Entities

- **推荐目标日**: `today` 或 `tomorrow`，用于确定账号时区下的目标自然日和界面文案。
- **真实天气快照**: 来自公开天气服务的城市、温度、体感温度、天气代码、概况、获取时间和真实来源。
- **每日推荐批次**: 当前账号在一个自然日唯一的一组三套方案；今天与明天分别占用不同日期。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可在 2 次点击内从今日切换到明日并开始生成搭配。
- **SC-002**: 今天与明天的目标日期映射正确率为 100%，两个日期互相覆盖次数为 0。
- **SC-003**: 天气服务成功时，展示城市、日期和天气值与同次公开接口响应一致率为 100%。
- **SC-004**: 天气服务失败、超时或响应无效的测试中，模拟天气和新推荐写入次数均为 0。
- **SC-005**: 旧模拟天气批次被当作当前有效结果展示的次数为 0。
- **SC-006**: 390px 宽度下日期切换、生成状态、天气卡和三套结果无水平溢出。

## Assumptions

- “实际天气”指来自公开天气服务的当前天气或预报，不代表气象观测绝对无误。
- 明日搭配采用官方日预报中的原始最低温度和最低体感温度，以优先避免穿着过薄；天气概况采用该日天气代码。
- 当前阶段继续只支持账号主动保存的中国城市，不申请设备定位权限。
- AI 失败后的规则推荐仍是允许的搭配降级；真实天气获取失败不允许降级。
