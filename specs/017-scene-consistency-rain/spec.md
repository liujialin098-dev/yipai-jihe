# Feature Specification: 场景一致性与雨天防水搭配

**Feature Branch**: `017-scene-consistency-rain`

**Created**: 2026-08-27

**Status**: Complete

**Input**: User description: "严格区分休闲、约会、正式与通勤搭配，保持整套风格一致；雨天可优先考虑冲锋衣、冲锋裤与防水鞋。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 场景不串台 (Priority: P1)

用户选择休闲、约会或正式场景后，希望整套衣服只表达当前场景，不再混入只属于其他场景的单品。

**Why this priority**: 场景选择是每日推荐的核心输入；如果结果串场，标题和理由即使不同也无法建立信任。

**Independent Test**: 使用同时包含休闲、约会、正式和通勤标签单品的固定衣橱，分别生成三个目标场景，逐件检查结果是否符合当前场景边界。

**Acceptance Scenarios**:

1. **Given** 衣橱同时有休闲、约会、正式和通勤单品，**When** 用户选择休闲，**Then** 结果不得使用仅标记约会、正式或通勤且未标记休闲的单品。
2. **Given** 衣橱同时有休闲与约会单品，**When** 用户选择约会，**Then** 结果不得使用仅标记休闲且未标记约会的单品。
3. **Given** 衣橱同时有休闲、通勤与正式单品，**When** 用户选择正式，**Then** 结果不得使用仅标记休闲或通勤且未标记正式的单品。
4. **Given** 一件单品同时明确标记当前场景和其他场景，**When** 生成当前场景推荐，**Then** 该单品仍可作为当前场景合法候选。

---

### User Story 2 - 整套风格一致 (Priority: P1)

用户希望一套搭配中的核心单品、鞋和可选外套表达同一场景，不能靠标题、理由或配饰掩盖互相冲突的衣服。

**Why this priority**: 单件合规并不等于整套协调，服务端必须对模型和备用推荐采用同一判断标准。

**Independent Test**: 构造一套含有当前场景核心单品和一件异场景单品的结果，确认系统拒绝整套结果并改用合法备用推荐。

**Acceptance Scenarios**:

1. **Given** AI 返回的某套衣服含有异场景单品，**When** 系统复验结果，**Then** 整批 AI 结果被拒绝并进入既有规则降级流程。
2. **Given** AI 服务不可用，**When** 系统使用规则生成，**Then** 规则结果遵循与 AI 相同的场景边界。
3. **Given** 当前衣橱不足以生成三套合法结果，**When** 用户请求推荐，**Then** 系统沿用衣橱不足提示，不得放宽场景边界或虚构衣物。

---

### User Story 3 - 雨天优先防水组合 (Priority: P2)

雨天用户希望推荐能利用衣橱中的冲锋衣、冲锋裤和防水鞋，形成更适合出行的完整防水组合。

**Why this priority**: 真实天气已经参与推荐，雨天应该影响单品选择，而不仅出现在理由文案中。

**Independent Test**: 在真实雨天快照与含完整防水三件套的固定衣橱下生成三套推荐，确认至少一套包含完整防水组合；再移除其中一类，确认系统不虚构、不强行拼接。

**Acceptance Scenarios**:

1. **Given** 天气为雨、阵雨或雷雨且衣橱有符合当前场景的冲锋衣、冲锋裤和防水鞋，**When** 用户生成推荐，**Then** 三套结果中至少一套优先使用完整防水组合。
2. **Given** 雨天但衣橱缺少防水三件套中的任一类别，**When** 用户生成推荐，**Then** 系统继续生成其他合法搭配，不虚构缺少的防水单品。
3. **Given** 非雨天，**When** 用户生成推荐，**Then** 防水单品不因本功能获得额外优先级。

### Edge Cases

- 一件单品同时标记当前场景与被排斥场景时，以明确包含当前场景为准，不误删可跨场景使用的基础款。
- 单品只有偏好风格、没有当前场景标签，且明确标记为被排斥场景时，场景标签优先，仍需拒绝。
- 通勤场景沿用已有画像，不因本阶段新增额外排斥范围。
- 仅有冲锋衣、冲锋裤或防水鞋中的一两类时，不触发“完整防水组合”硬要求。
- 雨雪天气使用不同判断；有雪不等同于本阶段定义的雨天。
- 炎热雨天仍需遵守既有温度与季节边界，不得为了凑齐防水组合使用明确仅适合冬季的外套。
- 三套之间仍不得重复单品，完整防水组合只需在库存支持时至少出现一套。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 为休闲、约会、正式三个场景定义可验收的异场景排斥边界。
- **FR-002**: 休闲推荐 MUST 拒绝未标记休闲、但标记约会、正式或通勤的单品。
- **FR-003**: 约会推荐 MUST 拒绝未标记约会、但标记休闲的单品。
- **FR-004**: 正式推荐 MUST 拒绝未标记正式、但标记休闲或通勤的单品。
- **FR-005**: 同时标记当前场景与其他场景的单品 MUST 保持可用，避免误杀跨场景基础款。
- **FR-006**: AI 生成、规则降级和最终结果复验 MUST 使用同一套场景冲突判断。
- **FR-007**: 每套推荐 MUST 继续满足完整上装/下装或连衣裙、鞋、季节适配、低温外套、跨套不重复和至少两个当前场景信号等既有要求。
- **FR-008**: 系统 MUST 准确识别雨、阵雨和雷雨，不得把雪天或普通阴天误判为雨天。
- **FR-009**: 系统 MUST 基于衣物名称和类别识别冲锋衣/防水外层、冲锋裤/防水下装与防水鞋三种防水角色。
- **FR-010**: 当雨天且存在符合当前场景、温度边界的完整防水三件套时，三套推荐中 MUST 至少有一套使用完整组合。
- **FR-011**: 当完整防水组合不成立时，系统 MUST 保持普通合法推荐，不放宽场景边界、不重复单品、不生成清单外衣物。
- **FR-012**: AI 提示 MUST 明确说明异场景硬边界和有条件的雨天完整防水组合要求。
- **FR-013**: 推荐失败和衣橱不足时 MUST 沿用现有用户可理解的反馈，不新增付费模型调用。
- **FR-014**: 内置演示衣橱 MUST 提供足够的男装/中性合法候选，使严格场景边界下四个场景仍可分别生成三套，并为新增单品提供安全棚拍素材。

### Key Entities

- **场景画像**: 当前场景的偏好风格、弱关联场景、明确排斥的异场景以及选择说明。
- **衣物场景归属**: 单件衣物的场景标签；当前场景标签优先于其他同时存在的标签。
- **防水角色**: 雨天搭配中的防水外层、防水下装和防水鞋三类角色。
- **天气快照**: 推荐目标日期对应的真实城市天气，其中天气代码决定是否进入雨天逻辑。
- **推荐套装**: 由当前用户活跃衣物组成、通过场景一致性、天气、完整性和跨套不重复复验的搭配。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 固定混合衣橱的休闲、约会和正式推荐中，异场景单品违规数为 0。
- **SC-002**: AI 结果、规则结果和最终复验对同一异场景单品的判断一致率为 100%。
- **SC-003**: 在雨天且完整防水三件套可用的固定样本中，3 套结果至少 1 套包含完整组合，达成率为 100%。
- **SC-004**: 在雨天但防水库存不完整的固定样本中，清单外衣物、错误补齐和跨套重复均为 0。
- **SC-005**: 既有四场景、真实今日/明日天气、账号衣着偏好和三套完整性验收全部继续通过。
- **SC-006**: 单次推荐继续保持既有 15 秒用户等待目标，且 AI 无效时只执行一次规则降级。

## Assumptions

- 场景标签由现有 AI 识别或用户编辑产生，本阶段不新增衣物字段和数据库迁移；允许扩充隔离演示数据以维持四场景验收能力。
- “不要出现其他场景衣服”按明确场景标签解释；只要单品明确包含当前场景，即便也包含其他场景，仍可使用。
- 防水能力以名称中的“冲锋”“防水”“雨衣”“雨裤”“雨靴”等明确语义结合衣物类别判断；仅凭普通功能面料不推断为防水。
- 完整防水组合是雨天的条件优先规则，不会覆盖温度、季节、用户衣着偏好、衣物归属、当前场景和跨套不重复等更高优先级边界。
- 本阶段不新增户外场景、不改页面交互、不调用新的天气或模型服务。
