# Research: 换一件、收藏与偏好反馈

## 决策 1：替换继续更新当日 JSONB 快照

- **Decision**: 服务端读取当前当日推荐，替换目标 ID 后调用现有完整验证器，验证通过再一次性更新 `outfits`。
- **Rationale**: SDD-005 已把三套定义为单个原子批次；MVP 换件无需拆分子表，单次更新可避免中间不完整状态。
- **Alternatives considered**: 为每套和每个版位建规范化表。可获得外键，但会扩大迁移、事务和页面读取复杂度。

## 决策 2：候选规则优先，AI 只可重排

- **Decision**: 先由服务端确定同类、当前用户、active、未占用、季节/场合兼容的合法候选；候选较多时可以由 AI 重排 ID，但超时或无效时保持确定性本地排序。
- **Rationale**: AI 不应绕过安全和搭配规则，也不应让基本换件依赖外部可用性。
- **Alternatives considered**: 让模型直接生成候选、允许推荐衣橱外商品。前者难以保证合法，后者超出私人衣橱边界。

## 决策 3：整套收藏保存不可变快照

- **Decision**: 保存标题、理由、标签、天气、场合和衣物 ID/名称/图片路径快照，并使用当前推荐版本生成稳定 `source_key`。
- **Rationale**: 今日推荐会覆盖，收藏必须保留用户当时喜欢的方案。
- **Alternatives considered**: 只保存推荐 ID 和 slot。刷新后内容会漂移，无法满足收藏预期。

## 决策 4：事件账本 + 派生风格分数

- **Decision**: 反馈事件保留来源、风格和权重；每次有效状态变化后按当前用户事件求和并更新 `user_preferences.style_scores` 与 `preferred_styles`。
- **Rationale**: 权重可解释、可重算，且直接复用现有推荐输入。
- **Weights**: 问卷排序 3/2/1，侧重点映射 +1；单品收藏 ±1；整套每个风格 ±0.5；换入单品 +0.35；查看事件权重 0。
- **Alternatives considered**: 只覆盖偏好数组、黑盒向量或模型训练。前者无来源，后两者超出 MVP。

## 决策 5：问卷采用单页 3 题

- **Decision**: 选择最多 3 个风格、最多 3 个常用场合，再选择“舒适/百搭/精致”侧重点；允许跳过并写入默认偏好。
- **Rationale**: 3 题满足范围要求，同时可在一次移动端表单中完成，容易验收和返回修改。
