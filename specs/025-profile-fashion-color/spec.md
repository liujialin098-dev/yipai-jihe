# Feature Specification: 时尚个人主页与彩色视觉层

**Feature Branch**: `025-profile-fashion-color`

**Created**: 2026-09-01

**Status**: 已完成，待部署

**Input**: User description: 学习 Whering 的年轻时尚表达，为衣拍即合增加可编辑个人主页、头像和昵称，并让应用整体更时尚多彩，同时保持原有功能和品牌辨识。

## User Scenarios & Testing

### User Story 1 - 查看个人衣橱主页 (Priority: P1)

用户点击顶部头像进入自己的个人主页，集中看到头像、昵称、账号类型、衣橱件数、已保存穿搭卡片数、穿搭日记天数、衣物利用率和近期穿搭卡片。

**Why this priority**: 个人主页是身份感与成果展示的中心，也为昵称、头像和分享作品提供稳定入口。

**Independent Test**: 登录任一账号打开 `/profile`，所有统计只来自当前账号，缺少日记或卡片时显示清晰空状态。

**Acceptance Scenarios**:

1. **Given** 当前账号有衣物、日记和穿搭卡片，**When** 打开个人主页，**Then** 页面展示对应统计和近期卡片，且不包含其他账号数据。
2. **Given** 当前账号没有穿搭卡片，**When** 打开个人主页，**Then** 页面引导前往每日推荐创建第一张卡片。

---

### User Story 2 - 修改头像与昵称 (Priority: P1)

用户可上传自己的头像并修改昵称。头像保存在当前账号私有目录，昵称为 1～20 个可见字符；保存后顶部入口和个人主页同步更新。

**Why this priority**: 用户明确要求个人资料可编辑，这是个人主页成立的核心能力。

**Independent Test**: 上传 JPG、PNG 或 WebP 头像并修改昵称，刷新后结果保持；超大或错误格式文件被拒绝，原资料不受影响。

**Acceptance Scenarios**:

1. **Given** 合法头像和昵称，**When** 用户保存，**Then** 当前账号资料更新，页面显示成功反馈。
2. **Given** 非图片、超过 5MB 或空昵称，**When** 用户提交，**Then** 页面明确拒绝且不覆盖原资料。

---

### User Story 3 - 感受统一的时尚多彩界面 (Priority: P2)

用户在首页、衣橱、推荐、个人主页和导航中看到同一组青柠、丁香紫、珊瑚橙与天空蓝色彩；色彩用于内容区分和重点操作，不改变功能位置，不牺牲文字对比度。

**Why this priority**: 视觉升级应形成产品气质，而不是只给单页随机加色。

**Independent Test**: 在 390px 视口浏览核心页面，品牌、导航和内容卡片保持统一，无横向溢出，文字与焦点清晰。

### Edge Cases

- 头像签名地址过期时只退回昵称首字占位，不阻塞页面。
- 新头像写入成功但资料绑定失败时保留旧头像路径，并删除未绑定的新文件。
- 用户重复上传头像时先写入新版本，绑定成功后清理旧版本，绑定失败可安全回滚且不产生无限历史文件。
- 匿名体验身份也可设置本设备可见的昵称与头像，但页面继续提示注册后才能跨设备恢复。
- 昵称只包含空白、控制字符或超过 20 个可见字符时拒绝保存。
- 统计查询部分失败时页面保留个人资料并将不可用统计显示为 0 或明确提示。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 提供 `/profile` 个人主页，并通过顶部头像入口进入；设置入口继续可达。
- **FR-002**: 个人主页 MUST 展示当前账号头像、昵称、账号类型、衣橱件数、穿搭卡片数、日记天数和 30 天衣物利用率。
- **FR-003**: 个人主页 MUST 展示当前账号最近更新的最多 4 张穿搭卡片，卡片点击后进入可继续编辑的画布。
- **FR-004**: 用户 MUST 可将昵称修改为 1～20 个可见字符；服务端 MUST 重新鉴权并限制只更新当前账号。
- **FR-005**: 用户 MUST 可上传 JPG、PNG 或 WebP 头像，文件大小 MUST 不超过 5MB；头像 MUST 存入 `wardrobe-images/<uid>/profile/avatar-<upload-id>.<ext>` 私有路径，绑定成功后清理旧头像。
- **FR-006**: 浏览器上传头像前 MUST 校验类型和大小；服务端绑定头像路径时 MUST 校验当前账号归属和严格路径格式。
- **FR-007**: 页面读取头像 MUST 使用短期签名地址；数据库和浏览器 UI 不公开私有对象路径。
- **FR-008**: 顶部入口 MUST 显示当前头像；无头像或读取失败时显示昵称首字占位。
- **FR-009**: 应用 MUST 使用统一的青柠、丁香紫、珊瑚橙和天空蓝视觉 token，重点覆盖背景气氛、内容卡、状态标签和导航选中态。
- **FR-010**: 视觉升级 MUST 保留正式 `BrandMark`、现有页面结构、Apple 式触感、减少动态和减少透明度降级。
- **FR-011**: 系统 MUST 保证 390px 无水平溢出、可见焦点、触摸目标不小于 44px，并避免仅用颜色表达状态。
- **FR-012**: 本阶段 MUST 不新增公开个人主页、关注、评论、社区动态、用户搜索或公开头像存储。

### Key Entities

- **个人资料**：当前账号的昵称、私有头像路径和简介展示信息。
- **个人主页统计**：当前账号衣橱、画布和日记的只读聚合。
- **近期穿搭卡片**：SDD-024 保存的当前账号私有画布摘要。
- **时尚色彩 token**：青柠、丁香紫、珊瑚橙、天空蓝及其浅色层级。

## Success Criteria

- **SC-001**: 合法头像和昵称保存后刷新仍保持，顶部与个人主页显示一致。
- **SC-002**: 两个测试账号不能读取、更新或签名访问对方资料、头像和穿搭卡片。
- **SC-003**: 个人主页全部统计与当前账号数据库记录一致，固定样本误差为 0。
- **SC-004**: 首页、衣橱、推荐、个人主页和导航在 390px 下无水平溢出，控制台无 error。
- **SC-005**: 开启减少动态或减少透明度后，资料编辑与页面导航仍完整可用。

## Assumptions

- `profiles.display_name` 继续作为昵称字段，不重复创建 nickname。
- 头像复用现有私有 `wardrobe-images` bucket 与当前用户首段路径 RLS。
- 个人主页仅为本人可见，不等同于社区资料页。
- 视觉方向学习 Whering 的“数字衣橱、编辑画布、多彩内容块”原则，不复制其商标、页面结构、文案或专有图形。
